# craft-datasec

独立的本地文本脱敏插件。仅包含同步 hook 和脱敏程序，不加载 Craft Context、知识、记忆、模型或 MCP 服务。当前版本 `0.1.2`。

## 处理范围

- 工具成功返回的文本：手机号、身份证、邮箱、IPv4、银行卡、API 密钥、密码、JWT、PEM 私钥。姓名规则默认关闭。
- 扫描 Java、Python、Markdown 等文本，不按源码扩展名跳过。
- 邮箱保留本地部分的首字符和完整域名，其余本地部分统一显示为 `*`；例如 `w1231321312` + `@123.com` 显示为 `w*` + `@123.com`。邮箱不创建可还原映射。
- 除邮箱外，同一会话的相同敏感值使用相同占位符；不同会话独立。凭据规则保留字段名，仅替换值。
- `Edit`、`Write`、`MultiEdit`、`NotebookEdit`、`apply_patch` 的输入可还原已知占位符，避免将占位符写入原文件。未知、截断或修改过的占位符拒绝写入。
- Bash 和远程工具参数不自动还原占位符，避免将原值意外放进命令或网络请求。
- 普通用户提示词直接放行，不扫描、不改写、不保存，也不因规则命中或本地配置、解析错误阻止发送。提示词中的敏感值可能原样发送给模型，请在粘贴前自行替换。工具结果继续自动脱敏。
- 直接 `Read` 常见图片、Office、压缩包等格式时拒绝处理，先导出纯文本。不是 OCR 或二进制脱敏器。

## 两端行为

| 宿主 | 工具结果的处理方式 |
| --- | --- |
| Claude Code | `PostToolUse.updatedToolOutput` 替换原结果，保留返回对象结构 |
| Codex | `PostToolUse.decision=block` 阻止原结果进入上下文和正在运行的代码模式脚本，通过 `reason` 同步返回脱敏文本 |

Codex 的此类结果是工具反馈。在代码模式中，工具 Promise 会拒绝，模型需要根据同步返回的脱敏文本继续；不进入人工复核或等待队列。不使用尚未支持的 `updatedMCPToolOutput`，也不使用仅改模型可见文本、未明确保证脚本拿不到原结果的替代路径。

契约依据：[Claude Code hook 文档](https://code.claude.com/docs/en/hooks#posttooluse-decision-control)、[Codex hook 文档](https://learn.chatgpt.com/docs/hooks#posttooluse)。本机环境为 Claude Code `2.1.304`、Codex CLI `0.163.0`、Node `23.11.0`；已做独立进程及打包后的 hook 协议回放，尚未在真实模型会话中启用并验证整条链路。

## 构建和检查

在仓库内已有 Node 开发依赖的环境中：

```sh
cd capability/craft-datasec
npm run build
npm run typecheck
npm run coverage
```

构建产物写入本插件的 `dist/hook.mjs`，只依赖 Node 标准库。运行要求 Node >=23，当前支持 macOS/Linux。独立版本和构建脚本不加入 Context 的运行时或发布目录；此命令不会安装插件，也不会修改宿主配置。

Claude 的本地加载入口：

```sh
claude --plugin-dir /absolute/path/to/craft/plugins/craft-datasec
```

从 Craft Marketplace 安装：

```text
/plugin install craft-datasec@craft-marketplace
```

```sh
codex plugin add craft-datasec@craft-marketplace
```

Codex 使用 `.codex-plugin/plugin.json` 和 `hooks/codex-hooks.json`。加载本地插件或分发包后须新建会话，并检查 hook 信任状态；只有配置存在不能证明 hook 已执行。不覆盖 `~/.codex/hooks.json` 或公司管理的 hook。

## 私有映射和配置

默认映射目录是 `~/.craft-datasec/<会话摘要>/`，与 `~/.craft_data` 无关。目录权限 `0700`，密钥和数据库权限 `0600`；拒绝不安全权限和符号链接文件。占位符使用带会话随机密钥的 HMAC，不使用可直接枚举手机号的裸哈希。

需要还原的原值仅保存在本地映射数据库，不写到 hook 消息、错误日志或构建包。邮箱仅做部分脱敏，不写入映射。同一输出中的重复值只处理一次，映射在一次事务中批量保存，避免逐条创建文件。事务失败会回滚；不同进程由 SQLite 协调。

映射用于后续编辑和恢复会话，因此不在每次工具结束时删除。会话仍需编辑时不能删除。映射目录属于本机敏感数据，不能提交 Git、上传或提供给模型；该目录的权限不是针对同一用户下任意命令的沙箱。当前没有自动清理策略。

可由本地启动环境显式设置：

- `CRAFT_DATASEC_DIR`：独立私有映射目录。
- `CRAFT_DATASEC_RULES`：受信任的本地规则 JSON 文件路径。使用后完全替换默认规则；不自动读取仓库提供的规则。

规则是数组，每项包含 `name`、JavaScript 正则 `pattern`，以及可选的 `flags`、`group`、`enabled`。`group` 指定只替换某个捕获组，默认替换整个匹配。`email` 规则的匹配内容须是完整邮箱，会按上述方式部分脱敏；其它规则使用可还原占位符。默认规则见 `capability/craft-datasec/rules.ts`。无效规则或全部关闭不会静默放行。自定义正则需要避免回溯过多的表达式。

## 明确的边界

- 规则识别属于启发式方法，可能误报或漏报，不等于企业级数据防泄漏系统。
- 工具结果 hook 不会撤销已经执行的命令，也不阻止该命令自行发送网络请求。原结果也可能先进入宿主本地日志或遥测。
- 不覆盖图片内容、宿主提前加载的指令/附件、远端托管工具、未经 hook 的工具路径，以及宿主未提供结果替换契约的工具失败事件。不要据此宣称“所有模型入口均已脱敏”。
- 运行期错误返回隐藏结果并要求停止；但宿主忽略无效的返回格式、进程启动失败或超时后的行为由宿主决定。当前无法用普通插件保证这些情况下绝不泄漏。需要逐版本做真实会话验收。
- 公司的 PII hook 独立运行，可能在本插件前就拦截；本插件不关闭、不绕过公司策略。仅调整 hook 顺序不构成兼容性证明。
- 对结构化结果中的数字敏感值，模型看到的是字符串占位符；它不是可直接执行的等价数据集。

### 性能实测

2026-10-20，macOS arm64、Node 23.11.0，默认九类规则，合成的手机号/邮箱/密码混合文本。核心与映射处理各运行 5 次，完整进程运行 3 次，下表为中位数；不是延迟上界或高分位指标。

| 输入 | 值分布 | 纯扫描 | 扫描及映射 | 含 Node 启动和 JSON 传输 |
| --- | --- | --- | --- | --- |
| 10KB | 重复值 | 0.59ms | 2.76ms | 57.78ms |
| 10KB | 不同手机号 | 0.46ms | 4.07ms | 59.40ms |
| 100KB | 重复值 | 5.16ms | 13.15ms | 109.44ms |
| 100KB | 不同手机号 | 4.97ms | 17.64ms | 89.37ms |
| 1MB | 重复值 | 38.00ms | 57.38ms | 165.19ms |
| 1MB | 不同手机号 | 42.07ms | 121.94ms | 242.74ms |

完整进程测量重用已建立的会话映射；扫描及映射首次调用的 1MB 不同值样本为 124.12ms。样本重复同一行直到指定大小，不同值场景逐行递增合成手机号。处理包含真实的私有目录、HMAC、SQLite 事务和输出序列化，不调用模型。宿主启动 hook、其他公司 hook、授权和网络耗时不在此表内。

主要成本是进程启动和映射保存。重复值在单次调用中缓存，多个映射在一次事务内保存。首个逐条文件写入方案在 10KB 样本即耗时约 500～600ms，已删除该方案。
