# Craft 个人 Agent 核心闭环设计

日期：2026-11-09  
状态：设计稿，等待用户审阅；未授权进入代码实现

## 意图

为愿意自行配置模型 Key 的非技术用户和技术用户，交付一条在 macOS 上可用的个人 Agent 主路径：用户交代竞品研究任务，Craft 搜索并阅读公开资料，生成带来源的 Markdown 文件；用户可以修改成果，关闭后重开，再要求补充竞品时只更新受影响内容。目标是把现有内核能力接成一条真实可用的工作，而不是新造 Agent 框架。

## 当前状态与问题

Craft 已有内置模型循环、任务与预算、来源／证据、审批、Experience 流程、工作区写入和会话续接等基础。当前默认 Workbench 的 Craft 分发仍走 `taskMessageSend` 对话路径，并在返回后将路由标记完成；它没有把默认用户请求接到持续执行和成果验收主线。浏览器动作有治理合同，但依赖外部适配器；自动化调度也在等待外部 Host。macOS 有若干 Workbench 验收材料，但不等于原生桌面安装和整条用户路径已验收。

因此主要差距是主路径集成与缺少内置公开网页读取能力，不是缺少一个全新的任务状态机。

## 目标

1. 首次启动无需 Craft 注册；用户选择兼容模型、填写自己的 Key、测试连接、查看能力与费用估算，并确认任务和每日预算。
2. 一项任务使用同一持久身份贯穿澄清、只读研究、写入审批、执行、验证、交付、暂停和恢复。
3. 在线资料仅限该任务明确要求的公开网页读取；来源链接和访问时间与结论一起交付。
4. 在用户选定的工作目录生成 Markdown 文件；报告区分事实、来源冲突、缺失项和推断。
5. 用户人工修改受到保护。后续补充要求只更新受影响段落或表格条目，并保留未改部分。
6. 项目范围内的明确纠正立即生效、可见、可撤销；不静默提升为全局偏好。
7. 达到必须由人决定的底线动作时暂停。超时、连接中断、执行结果未知或无法核实的资料均不能默认放行或标记完成。
8. 通过可重复的模拟任务、故障注入和跨仓端到端回放验证交付机制；模拟结果不能被表述为真实用户收益证明。
9. 提供可安装的 macOS 桌面版本和基本系统通知；原生安装、升级、通知权限及点击回到正确任务需要真实安装包验收。

## 非目标

- 本版本不实现 IM／邮箱收发、远程电脑、外部助手安装、跨设备同步、定时自动运行、完全自动放权或自动晋升学习资产。
- 本版本不建设完整 Markdown 编辑器；Workbench 负责任务、来源、预览、差异和交付入口，实际文件仍由用户持有并可用其他工具编辑。
- 不复用 OpenHands、LobeHub、Orca、Multica 的代码、SDK 或框架。
- 不要求真实用户研究阻塞功能实现；但没有独立真实任务证据时，不宣称产品已被证明更省心。
- 不把模型生成的自评、页面上的“成功”文案或脚本执行结束当作事实正确性的证明。

## 约束与已确认决定

- 首发平台：macOS。其他平台保持代码兼容目标，不作本版体验或发布承诺。
- 首发场景：公开网页竞品研究与 Markdown 交付。
- 公开网页访问按任务授权只读处理。不访问登录／付费页面，不复用浏览器登录态，不下载网页附件或可执行文件，不提交表单，不对外发送。
- 首次使用由用户提供模型 Key；审查模型默认复用主模型，但使用独立对话，只读取动作摘要和来源标记。
- 任务默认使用自动审批档，仍保留硬性底线：改权限或授权、读取或使用密钥、安装扩展、修改沙箱外系统设置、不可撤回的对外发送均需用户决定。预测花费将超过上限时先暂停并展示已花金额和预计追加费用；用户可显式调高预算并留记录，批准某项动作本身不能绕过预算上限。永久全放开不提供；临时授权必须限制对象、动作、期限和额度。
- 定时执行后置；先证明一次任务可靠完成和续做。
- 纠正默认应用在当前项目范围，显示记忆内容并提供撤销；全局记忆同步和自动偏好推断后置。
- 首次使用不要求模型 Key 之外的新凭据，是从“用户自备模型 Key、免注册”推导的产品约束；若网页搜索实现无法满足，先提出方案，不得悄悄增加第二套凭据配置。
- 数值预算默认值和正式收益门槛不在缺少模型实测、价格数据和基线的情况下臆造。实现时必须显示实际配置值、预计费用及不确定性。

## 方案比较与选择

### 方案 A：重写一个新的 Agent 内核

从任务规划、审批、持久执行、工具、记忆和评测重新实现一套。边界看似统一，但会复制 Craft 已有对象和安全合同，造成双状态源、迁移成本和长期维护分叉；不选。

### 方案 B：继续逐项补功能，不设跨仓完整交付线

可以独立推进浏览器、审批、记忆或 UI，但默认用户请求仍可能停在对话层，用户无法拿到一个完成的工作闭环；也与用户希望避免碎片化推进的要求冲突；不选。

### 方案 C：沿现有 Verified Work Loop 做一次跨仓纵向交付

复用 Craft 的任务、权限、预算、来源和执行器；由 Workbench 承载 macOS 首发体验；由 craft-eval 固定端到端、故障和安全场景。仅为公开网页读取补一个受限的内置实现，完整任务状态仍由既有主线负责。该方案保持已有领域边界，同时直接打通用户看到的结果；**本设计选择方案 C**。

## 核心使用路径

1. **准备：**用户添加模型 Key、完成连接与能力检查；选择工作目录并确认单任务和每日预算。Key 使用操作系统提供的安全凭据存储，诊断信息默认脱敏；具体存储实现由实施前安全审查确定。
2. **交代：**用户输入竞品名称和目标。缺少会改变比较结论的地区、币种、计费周期或产品档位时，助手一次性提出必要澄清；不必要的信息不阻塞。
3. **研究：**内置助手发现并读取公开页面，记录 URL、页面标题、读取时间及具体支持的结论。网页正文始终视为不可信输入，不可改变系统规则。
4. **合成：**Markdown 报告包含可比较字段、来源链接与访问时间；对矛盾价格、地区差异、促销条件、缺失字段和推断单独标注。没有足够证据的字段写“未查到／无法核实”，不补造数字。
5. **交付：**文件写入用户选定工作目录。普通本地新建和可撤销修改按任务权限执行；覆盖、删除和对外发送遵守已确认底线。完成状态绑定文件版本、来源和验证回执。
6. **续做：**关闭重开仍能看到目标、已采来源、执行状态、待决定动作和成果版本。用户要求添加竞品时只读取和改动受影响内容，检测到人工修改则保留并提示冲突，不整份覆盖。
7. **纠正：**用户纠正排序、字段偏好等时，当前相关任务立即应用；明确展示“已记住”内容和项目范围，提供撤销。自动推断仅作候选，不提升权限。

## 三仓库交付边界

| 仓库 | 本版责任 | 必须接通的关键路径 |
| --- | --- | --- |
| craft | Runtime、内置助手、公开网页只读适配、来源与任务状态、审批、费用与预算、恢复、项目纠正记忆 | 默认 Workbench 请求进入 Verified Work Loop；在同一任务下执行读取、必要澄清、文件写入、验证、暂停和续做；外部网页内容不能进入可信指令层 |
| craft-workbench | macOS 桌面交付、模型配置、任务输入、实时进度、待审批、来源检查、Markdown 预览／差异、接管、恢复和通知 | 不再把普通 Agent 请求仅作为对话消息；页面显示真实任务状态、当前权限档、来源和待处理动作；刷新或重连保留草稿与已读内容；通知可回到绑定的任务与决定 |
| craft-eval | 固定场景数据、成对回归、E2E 和报告 | 同一版本绑定代码、模型配置、预算和模拟资料；区分程序判定、模型判断和没有外部证据的结论；失败与 inconclusive 不算通过 |

三仓只构成同一发布列车，不创建第二套任务、审批或文件真值。跨仓接口以现有包版本和契约为准，扩展字段应可向后兼容；如确需不兼容变更，先记录迁移和恢复方案。

## 验收方式

用固定的合成竞品网站和文件跑完整模拟任务，覆盖首次配置、正常研究、网页冲突／伪指令、来源缺失、超时／断线、预算耗尽、待审批、写入失败、重启恢复、人工修改保护、追加竞品和纠正撤销。

每个端到端用例至少检查：

- 所有输出数字都绑定到支持它的来源；冲突或缺失有明确标记。
- 所有来自竞品研究的价格、规格等数值结论都绑定到支持它的来源；冲突或缺失有明确标记。
- 只读取本次任务授权的公开来源；不得模拟登录、读取凭据、下载网页附件或可执行文件、提交或对外发送。
- 报告位于指定目录、为 Markdown 格式，且与任务／来源／文件版本关联。
- 故障后不遗失已确认状态，不盲目重复未知副作用，不覆盖用户修改；文件版本漂移或无法定位局部修改时必须暂停，不得整份覆盖。
- 单任务与每日预算计数一致，取消、超时和未完成状态可读回。
- 项目纠正立即生效，可检查和撤销；不泄漏到其他项目。

模拟验收通过只说明这些固定机制按合同工作，不代表实时网页覆盖率、模型事实准确率或用户节省了时间。发布前另需一个固定 macOS 安装包和真实模型／浏览器读取路径的运行证据；还要从已安装应用验证启动、升级、系统通知权限和通知回跳。真实用户效果未采样时标为“未验证”，不阻塞内部开发。

## 主要风险

- **网页变化、反爬和来源质量：**读不到时显式部分交付；不能以模型自评填补缺失证据。
- **网页提示注入：**网页内容隔离为不可信材料，动作和权限仍由 Craft 固定规则判定。
- **长任务与来源量：**限制来源数量、总时间和输出；达到额度后保存进度、告知用户，不重置预算续跑。
- **人工修改冲突：**以文件版本摘要和局部变更定位；无法可靠对齐时暂停对应更新，不覆盖整份文件。
- **沙箱边界：**当前本地进程沙箱不保证工作区外文件隔离和网络拒绝。凡依赖更强隔离的自动执行路径，须使用已验证的隔离后端或保持人工审批，不得把目录限制宣传为 OS 沙箱。
- **平台承诺：**已有 macOS 浏览器界面证据不等同 Tauri 原生包、安装升级、通知和系统权限已通过验收。

## 交付顺序

1. 先固定一个版本化场景合同和安全测试集；浏览器与本地文件的读写权限在自动实现前经静态规则过滤。
2. 接通默认任务入口到现有 Verified Work Loop，并实现受限的公开网页读取与来源回执。
3. Workbench 展示真实任务进度、澄清／审批、来源、Markdown 成果、重连和恢复。
4. 接入项目级纠正、局部更新、文件版本检测及不覆盖人工修改。
5. 以 craft-eval 合成站点和故障案例跑跨仓 E2E；修复后形成绑定版本的报告。
6. 真实安装、模型和公开页面路径单独记为运行证据；不把模拟结果改写成真实用户价值结论。

## 留给实施者

- 在不增加模型 Key 之外的初始凭据负担前提下，选择最简单、可审计的公开搜索与读取方式；先调查现有 adapter 是否可作为内嵌传输，不要引入平行浏览器框架或依赖外部 Agent。
- 读取并复用三仓最新调用链，列明每个旧入口如何迁移及兼容；保留 `NEEDREAD.md` 之外用户未提交改动。
- 每项新增行为使用既有权限、预算、任务和事件合同；新增/修改代码按仓库覆盖要求补充测试。
- 明确 macOS 原生安装包、系统钥匙串和通知当前是否可实现及所需组件。若需新依赖，先在方案中写清由哪个验收条件需要它。
- 预算默认值、允许的公开来源上限、模型型号和真实用户样本由实测及产品输入确定，不在设计稿中虚构数字。
