# Craft Context 经验沉淀与存储设计

状态：讨论稿，2026-11-27。记录本轮已确认的方向，实施细节和验收仍需结合代码核实。

## 目标

从用户实际工作中发现后续有价值的知识、方法、脚本、设备与位置，保存到合适的子能力，并在后续任务中能够找到、核对和使用。覆盖开发、排障、环境操作、数据分析及文档任务。任务结束时判断是否存在可复用内容，允许明确无新增经验。

## 领域与归属

- Memory 保存稳定偏好和决策。
- Knowledge 保存可核对的事实、约束与来源。
- Experience 保存操作方法、排障经验和脚本。脚本具有项目或全局作用域，记录用途、输入、前置条件、使用方法、验证结果和版本或摘要。
- Notes 保存实际观察到的设备、目录与文件位置。
- 项目经验默认归项目。跨项目通用内容经去标识化、独立证据和评估后产生全局候选。用户偏好使用全局 Memory 的独立规则。

脚本本体保存在项目文件或全局可管理位置，Experience 持有可核对引用与摘要。引用失效或内容变化时提示复核。执行脚本沿用实际任务的权限和副作用边界。

## 捕获与使用

任务结束时根据实际结果和可核对来源判断价值，分别向对应子能力提交候选。候选记录适用条件、来源、验证状态、限制和必要的失败恢复方式。区分任务终态、候选创建、审核、可检索、可执行和后续效果，不能以候选存在证明实际复用或效果。

当前 Skill 的 Experience finalize 主要针对已验证的文件修改任务。需要核查并补齐纯排障、环境操作和其他非代码任务的捕获入口，同时核实 Host 调用、Worker、候选处理、检索、反馈和独立评估的实际运行状态。保留各子能力的治理责任。

## 存储与迁移

长期数据仅保留项目和全局层级。运行所需会话上下文驻留内存，任务结束不持久化。项目数据存于项目目录的 `.craft_data/`，全局数据使用全局数据根。项目运行数据由 Git 忽略。

先只读盘点现有会话和项目分区，生成项目归属与迁移预览。可明确归属且符合子能力规则的数据迁入项目，逐项回读核对后清理对应旧会话记录。失败或无法归属的记录保留并列出。迁移需考虑 SQLite 一致性、并发写入、失败恢复、重复执行、来源引用和旧路径兼容。

父工作区与子仓库分别具有项目边界。多仓共有内容归父工作区，子仓专属内容归子仓。

## 两份手册

- `eval-all/AI_WORKSPACE_OPERATIONS.md` 中多仓约定归父工作区。
- `d-simu/docs/runbooks/standardized-conversation-agent-setup.md` 中专属内容归 d-simu。

按来源位置和摘要生成候选。事实进入 Knowledge，操作与恢复方法进入 Experience。机器和环境快照保留日期与来源，实际观察到使用的设备和目录才进入 Notes。候选经过各自治理后使用。

## 验收

1. 不同类型的已完成任务分别验证可复用经验捕获和无新增经验的结果。
2. 项目与全局数据正确隔离，项目数据确实位于对应目录，跨项目读取受到约束。
3. 项目和全局脚本均能按适用场景检索，引用变更或失效能够被发现。
4. 会话内容不再持久化，来源证据仍足以支持候选审核和撤销。
5. 迁移覆盖旧分区、目标已有数据、冲突、重试和中断恢复，成功迁移逐项回读，未归属数据可见。
6. 两份手册的代表性条目有准确来源、归属和候选状态。候选、启用、实际使用和独立效果分别报告。
7. 正常 Host 入口、Worker、检索和反馈各自验证。增量可执行行与分支覆盖率分别达到 100%，报告差异基线及覆盖数。
