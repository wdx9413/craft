# v0.12.36：Knowledge / Memory / Experience 完整闭环

## 已实现的本地机制

- Git remote 优先的 canonical project identity；本机路径仅作为可迁移的 alias。
- Scope 栈按 `task → project → user → explicit-global` 解析，不扫描所有项目 scope。
- Knowledge 以 Source Revision、Fragment、Evidence、Candidate 与结构/语义复核保鲜；`craft_evidence_record` 和 `craft_knowledge_source_ingest` 可单独通过 Knowledge MCP 使用。
- Memory 记录 topic、观测/生效时间、TTL、撤销和 supersede 历史；冲突不会随机注入 Context。
- Keyword、Vector、Hybrid 走真实 Retrieval Port；无 embedding 凭据或 Provider 时明确回退 keyword。
- Experience 从脱敏、真实终态 Observation 形成 Candidate；Graph 仅在分支、并行汇合、审批、恢复或补偿有证据时允许出现。
- Bundle 升级为 schema 3，携带 canonical scope、alias、来源 revision、fragment、Evidence、Ledger、Observation、Procedure Markdown 视图及 Workflow/Graph 的 JSON 定义、Candidate 以及设备/导出/cursor 元数据。导入会在目标机器重建结构化定义的本地引用；旧 Bundle 若仅含机器本地定义路径则降为待复核，不能继续路由。导入只有 add、duplicate、conflict；冲突生成 Candidate，不覆盖本地事实。内置目录/Git 工作树 Transport 只写受校验 JSON，Git 提交和推送仍由用户显式完成。
- Vector/Hybrid 仅在安全配置已持久化、评测 eligible 且当前健康时调用；真实调用失败会记录 Receipt 后回退 keyword，连续临时故障会短暂熔断。
- DeepSeek 的上下文缓存采用官方的服务端自动缓存：Internal Host 保持历史前缀字节级稳定、把当前输入作为动态后缀，并只在响应实际返回 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 时记录命中。Craft 不发送虚构 cache key，未返回 usage 时 Receipt 明确为 `unavailable`。
- Experience Workflow/Graph 的权威定义分别以受管 JSON 落在 `~/.craft_data/experience/procedures/workflows/`、`procedures/graphs/`；`md/workflows/`、`md/graphs/` 只是审阅视图。Prompt Procedure 保持 `md/prompts/` Markdown 正文。经 Shadow、Held-out、Signoff、Canary 后才可路由；导出禁用 Skill 草案时，结构化资产还会随附 `PROCEDURE.json`。
- `WorkControl` 是持久任务的唯一接口：`prepare / advance / decide / resume / get`。普通 `turn` 不建 Task Run；目标、计划、执行、验收与学习共用 Policy、Trace、Receipt、State 与 Acceptance 账本。连续两次无进展会生成 Handoff，不能无限重试。
- 可自动运行的 routeable Workflow 在每次执行前先过 Run Eligibility：只有仍处于活动状态、尚有配额且未陷入无进展时才运行；只有独立验收产生新的进度才结算一个配额。重复无进展会留下 Checkpoint/Handoff，不会静默空转或消耗模型/执行预算。
- Ticket Dispatch 是独立的只读 Candidate 能力：Host 提供已观察到的 Issue、依赖和仓库状态后，Craft 生成 `ready / blocked / needs_human` Dispatch Ledger，并以固定 Case 评测分类。它不能调用 Tracker、创建 worktree、Draft PR 或合并。后续 Forge 请求必须同时绑定已 routeable 的 Experience Procedure、同版本 Domain Kit 应用、项目仓库/分支策略、同 Ledger 的 eligible 评测及显式审批；默认只产生 `prepared_for_adapter` 请求，尚无配置的 Forge Adapter 明确返回 `unavailable`。
- `Workflow`、`Graph` 与短 `Prompt Procedure` 统一为 Experience Procedure 格式；只有 routeable Procedure 才可被决策点上下文选择。它与 Capability Registry 中的已安装 Skill/Workflow 分账；日常 MCP 使用简短 `craft_procedure_*` 名称。旧 Workflow Evolution/DAG 名称不再公开安装或 MCP 执行。
- 公开分发收敛为 `craft`、`craft-knowledge`、`craft-memory`、`craft-experience`，由 ReleaseCatalog 生成 Manifest、Marketplace 与打包校验。

## 自动化边界

Light Maintenance 可在 SessionEnd 或本地 tick 幂等执行；Review/Deep 仍要求空闲、租约、预算和模型可用。低风险、只读 Knowledge 可以在结构和 Host/Provider 语义复核均达阈值时自动晋升；涉及权限、Capability、外部写入或 Workflow 路由的内容仍必须经过独立 Evaluation/Gate。

## 验证状态

本版已有确定性 fixture、类型检查、MCP/插件 smoke 与离线回归测试。真实 Codex/Claude Hook 需要用户信任插件后才运行；真实 Provider、向量质量和业务收益仍必须由显式配置的配对 Trial 证明。未配置 Provider 时返回 `unavailable` 或可解释的 keyword 回退，绝不伪造真实模型复核。
