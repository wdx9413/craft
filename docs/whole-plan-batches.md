### 当前执行限制合同与证据

- `timeout_ms`（1000–86400000 毫秒）固定进派发摘要及回执；与循环时间预算取较早截止。模型传输、审批和动作收到同一取消信号。恢复沿用原始期限；无检查点时使用持久化启动时间，时间缺失或损坏则拒绝恢复。忽略信号的自定义适配器仍需等待返回确认状态。
- 请求 `max_tokens` 为 4096 与循环剩余 token 的较小值。HTTP 两种协议均拒绝非正安全整数上限。累计计费依据实际用量，字符估算不作为厂商计费上界。
- `max_budget_usd` 要求固定版本单价和 `ModelTransport.quote` 对该请求全部计费输入 token 给出可信上界。缓存按普通输入和缓存输入较高单价预留，输出按请求上限预留，向上取整至微美元。预算账户按派发隔离，预留先于调用；调用后按实际费用结算。
- 传输失败、缺失用量、超出报价等情况保留预留。恢复发现未结算调用时停止，避免重新消费。回执关联预算账户、预留、报价输入上界及输出上限。报价不足不发请求，也不记为已发生模型请求。
- 默认 HTTP 与 Codex 传输尚无可信报价能力，不能启用美元硬上限；模拟适配器已覆盖成功、额度不足、报价异常、取消、能力丢失、用量未知、报价违约、缓存价较高和中断恢复。可信报价是适配器合同，无法阻止不遵守报价的外部供应商实际多收费；违约后停止动作并保留证据与占额。

集中证据：内部 Host 组合 149 项通过，行/分支/函数覆盖均 100%；共享 Task Run 启动已覆盖预算读回与结算。Workbench `npm test` 通过（232 项及 Context Audit 14 项）；Eval `npm test` 通过（147 项、构建套件 1 项及 Context Audit 11 项）。后三仓检查属于本地与模拟证据，非真实厂商报价、远端运行或完整 A 批次验收。A 批次仍需完整成果验收矩阵及真实报价适配器，不标记完成。

### 成果重新验收合同

文件产物的显式重新验收已覆盖真实本地文件流程：模拟 Host 写入文件，首次校验通过；人工改坏文件后创建新评测任务，摘要校验失败；修复后第三轮通过。Task Run 的交付动作随当前 assessment 变化。文件变化不会凭空触发新的验证，用户可在任务页面点击“重新验收”，也可通过 HTTP/MCP 发起新轮次；此场景不宣称自动文件监视已完成。

重新验收不覆盖已完成 trial/outcome。结论或证据变化时生成新 trial，assessment 保存当前 `outcome_id`；计划查询、启动查询和幂等评测回执读当前结果。待验收时不返回历史通过结果。相同证据重复评估复用 outcome，旧结果及其证据保留。整个 assessment/outcome/交付投影更新在存储事务内完成。

### 验收提交与 Trace 恢复

人工确认、直接检查记录、评测回执在主库事务内完成，失败时不保留孤立证据、部分检查或半完成任务。重新验收后的人工与直接检查接口必须带当前 `plan_version`；首轮保留旧调用兼容。损坏、缺失或过期租约不能提交，已经停用的评测器也不能利用旧版本授权提交结果。

Trace 分片与主库不是同一数据库。验收结果和 `acceptance_trace_outbox` 在主事务一起提交；最外层服务操作提交后同步 Trace，内建验收 worker 也重试待同步项。Trace 事件有固定幂等标识，Trace 完成后再确认待同步项，确认失败可以重试；已有终态与目标结论冲突时保持待同步并报告失败数。不宣称跨数据库原子事务。

故障模拟覆盖主数据写后失败并回滚、同请求重试、Trace 分片失败、同步确认失败及终态冲突。相关 58 项回归、存储与 Trace 分片 66 项回归通过；新增 Trace 同步方法 25/25 语句、14/14 分支覆盖。整批成果矩阵与后续批次仍保持未完成。

### 执行停止、清理未知与恢复

POSIX 停止使用本次执行的独立进程组；根进程先退出且子进程未继承输出管道时，返回终态前仍强制清理该组。Windows 使用带 `/T /F` 的 shell-free `taskkill.exe`，有执行时间/输出上限并等待结果；并发停止请求复用同一次清理。

Windows 清理失败产生专用错误，不制造已停止回执。Codex、Claude、通用 CLI 把清理未知写入派发记录并交给共享 Host Run；Task Run 显示未知结果和人工交接，原派发直接执行及启动重试均被阻止。恢复要求确认原 Runner 已停止并匹配 owner，随后清除清理未知标记、刷新交付与任务状态，才允许新尝试。工作台显示“执行清理待确认”，不会把这一状态当成正常失败重试。

真实本地测试覆盖忽略 SIGTERM、保留管道、根进程先退出且后代无共享管道；Windows 路径使用系统调用模拟，验证调用参数、等待完成和失败恢复，不是 Windows 实机证明。主动创建新会话/脱离进程组的后代仍不能依靠 POSIX 组信号隔离，A 批次继续保留该边界。

相关 86 项回归通过；共享执行器行/函数/分支原生覆盖均 100%，覆盖门禁纳入对应测试。Workbench 完整测试通过（236 项及 Context Audit 14 项）；core/common 构建与编译后 Host 冒烟通过。未发布或修改用户执行端配置。

### 工作台精确恢复入口

工作台的“执行清理待确认”按运行展示停止确认复选框和操作按钮。用户必须明确确认原执行端及其子进程停止，提交当前运行版本并记录当前操作者；按钮不会终止进程或自动重新执行任务。失败时恢复按钮可用并提示刷新状态。

HTTP `POST /api/host-runs/:id/recover` 与 MCP `craft_host_run_recover` 使用同一精确恢复合同：`run_id`、数字 `run_version`、`actor` 和 `confirmed_original_runner_stopped=true`。服务从目标运行解析 owner；显式提供不匹配的 owner 会被拒绝。只恢复选中的运行，过期版本与仍由本进程执行的 Runner 被拒绝。原 owner 范围的孤儿恢复方式保留兼容，精确恢复不会扩大到同 owner 的其他运行。停止确认以 `explicit_operator_confirmation` 标记，不能当成系统自动观察到停止的证据。

### 失败后的受控新尝试

`taskRunRetry`、HTTP `POST /api/task-runs/:id/retry`、MCP `craft_task_run_retry` 以及工作台交接快照的“创建新尝试”共用合同：固定旧 Task Run、启动和 Host 运行版本，提供操作者、完整新指令和安全的新尝试编号。一个源运行只允许一个后续尝试；重复请求复用同一回执，改变同一编号的请求会冲突。工作台在网络结果不明时保留尝试编号和原请求，历史快照显示后续尝试而不再提供重复重试按钮。

新尝试保留工作区、沙箱、已保存的模型选择和执行端支持的限额。内部循环限制已贯通共享启动入口，重复准备比较限额，不能把变更后的时间、美元或循环预算当成原请求。新的控制合同保留原作用范围及同一激活/预算引用并重新校验，关闭的预算账户不能复活；环境和预算原始快照必须匹配，否则要求新准备。原模型调用仍有未结算占额时阻止重试，不以新预算账户掩盖旧费用未知。

准备阶段在主库事务内创建合同、派发、Task Run、验收和重试关系，提交前不调用模型。只读新尝试提交后启动，写入新尝试等待新审批，旧授权不能重复消费。准备持久化失败时主库准备记录回滚；提交后启动失败保留可继续的 prepared 状态，重发同一请求不另建尝试。原 Task Run、启动、Host 和验收结论保留。

验收失败也可返工：复制当前验收条件、评测器版本和输入，不复制旧检查结果；评测任务必须等新执行完成后才能领取。知识绑定重新校验并保留原上下文摘要，不退化为无绑定启动。专用激活上下文及 Fabric/外部编排任务仍要求原准备入口，不能静默丢失其执行合同；非默认环境/预算快照目前由技术接口提供，不在普通页面补造。

### 未知模型费用到人工对账、结算与新尝试

### 孤儿执行停止、费用超额与新尝试的完整恢复

精确 Host Run 恢复在记录操作者停止确认的同一主库事务内，将关联的 prepared/running 内部派发改为 interrupted，绑定 Host Run 编号、版本及确认来源。后续直接执行及 resume 均拒绝，不补造模型执行回执。任务、派发归属不一致或写后失败时整笔恢复回滚。历史已中断但缺少确认的运行，可按当前版本补充确认；旧 owner 批量接口维持原兼容行为，不凭空补操作者。恢复完成后刷新所有相关交付和 Task Run 投影，不依赖历史结果观察回调一定成功。

人工对账允许这一明确停止的派发，但再次核对绑定 Host Run 的任务、派发、版本、状态及明确确认来源。工作台提供停止确认入口，运行中的本地执行器仍由服务拒绝恢复；确认只是人工声明，页面不会替用户终止进程。任务历史保留“内部执行停止确认”事件，模型调用未知费用在对账前继续占额。

超预留账单要求额外 `confirmed_overrun=true`，页面提供独立确认框。金额按实际入账，原预留释放，预算上限不增加，已用额度可以超过上限并产生负余额；旧账户不能再预留资源。只有与该预留、派发、金额、操作者匹配的人工证据和对账记录同时明确确认超额，预算结算才允许 USD 超额；不能借此结算其他资源或用普通预算入口绕过证明。历史页面显式标记已确认超额，原用量与执行回执仍不改写。对账清除未知占额后，按受控新尝试合同准备新执行，原尝试保持 interrupted。

### 暂停、交接、重新授权续做与成果复验

任务页提供暂停、恢复观察和取消按钮；交接快照入口继续保留。暂停/取消要求填写原因，明确提示在途执行只会尽力停止，已发生的修改保留。恢复只切回观察状态，不重放旧 Host；被停止的任务经最新交接快照进入受控新尝试，写入再次审批。取消后的当前尝试不能恢复。

暂停、恢复、取消和交接共同支持数字 `task_run_version`。任务页总是提交展示版本，旧版本、非整数或无效版本在生命周期改变及 Host 取消前拒绝；MCP 精确声明整数类型。未提供版本的既有技术调用保留兼容，不能把它们描述为强制并发令牌调用。界面处理空原因、取消输入、服务冲突和网络失败，失败后恢复按钮，成功后重新读取状态。

### 有界返工、共享入口与待处理

`workRetryPolicy` 从持久化 `work_launch.retry_of` 向前追溯，返回根启动、已用返工次数和固定三轮上限，不采信客户端计数；损坏、跨任务、循环或过长祖先链拒绝继续。初始尝试不计入三轮，最多允许初始执行加三次新尝试。轮询、重复回执和同一编号的幂等重发不增加次数；已提交但尚待启动或审批的新尝试占用一轮，准备写入回滚则不占轮次。

限制放在共享准备记录入口，Task Run、普通启动和知识绑定路径共同执行。每个源启动只允许一个后续启动，不能从历史节点另建分支绕过轮数；重发已提交的同一启动仍返回原结果。重试保持任务归属，源执行必须已失败、取消、中断，或当前版本验收明确拒绝；旧轮次的失败不能给当前通过结果提供重试资格。Task Run 达到三轮且仍需返工时进入 `rework_limit`，安全下一步为补充证据并重新规划，不生成第四次执行。

普通启动准备也使用主库事务创建派发、启动和验收记录，提交后才启动只读 Host；故障注入验证写后失败整体回滚且无执行调用。继承知识绑定、预算未知占额拦截、原审批和成果复验仍沿用既有合同。任务页展示返工用量及上限；当前且活跃的耗尽 Task Run 生成控制台人工待处理项，过期运行或交付投影不产生该提醒，重复刷新不会新增轮次或重复卡片。

### 责任接单、转交、释放与受控续做

`taskRunAssignment`、HTTP `POST /api/task-runs/:id/assignment`、MCP `craft_task_run_assignment` 和任务页共用 claim/release/transfer 合同。责任记录按任务唯一，跨 Task Run 和后续尝试保留；每次动作必须提供操作者、原因、当前责任版本（首次为 0）及安全的请求编号。接手和转交还要求当前交接快照编号、版本；快照绑定目标、执行、验收与当前负责人引用。任务、状态、目标或负责人改变后，旧快照不能继续用于接手或转交。正在由 Host 处理时须先暂停或等待，取消后的当前尝试不能接手。

同一任务已有负责人时拒绝重复接单；只有现任负责人可释放或转交，转交须指定不同的接收人。共享准备、生命周期操作、受控重试、启动和审批入口检查负责人，技术调用需显式传入原有操作者字段；责任不会随新尝试重置。此为现有可信接口上的协调约束，不新增身份认证或权限授予系统，也不代替直接执行端的沙箱与授权。接单不调用模型、不改变执行及验收结果，写入续做仍走原审批路径。

责任记录、幂等回执和任务时间线在主库事务内提交。相同请求重放返回当前责任状态而不重复动作；相同编号改变内容冲突；事件写后失败整体回滚。释放无需依赖已经过期的执行快照，避免把负责人锁住。任务页显示当前负责人，只向本人提供释放和转交，接手/转交使用当前人工待处理快照；网络结果未知时保留同一请求编号和内容。页面和接口不发送消息，也不把填写接收人解释为已通知对方或已完成任务。

### 冻结成果、独立审查、返工继承与复验

`workReviewFreeze/Get/Report`、HTTP `/api/task-runs/:id/freeze-review`、`/api/work-reviews/:id` 与 `/report`、MCP `craft_work_review_*` 和任务页共用审查合同。冻结由当前负责人或未接单任务的声明产出者发起，固定 Task/Task Run/Host/启动/控制合同/验收版本，以及环境与预算摘要。只接受已经完成且清理已确认的活跃运行。相对路径限定在启动工作目录内，拒绝链接和非普通文件；最多 100 个文件、合计 10 MiB，读取有实际字节上限，增长越界拒绝。

冻结文件按实际字节和 SHA-256 独立保存在主库的版本化记录，清单保存固定引用，读取验证摘要与大小，不从当前工作文件补造历史内容。冻结会开启新一轮验收，旧检查和结论保持历史，新一轮程序检查及人工审查重新等待；冻结、清单、审查策略与验收轮次同事务提交，失败整体回滚。文件路径验证沿用本地可信工作目录边界，不宣称隔离恶意并发文件系统进程。

审查人必须区别于声明产出者及当前任务负责人。发现逐项绑定冻结文件，分为阻塞缺陷和建议；通过不能包含阻塞缺陷，返工必须提供阻塞缺陷，证据不足可提交 blocked。提交再次核对任务、执行、控制合同、验收版本、冻结内容完整性及当前文件摘要；变化时必须重新冻结，Reviewer 接口没有修改候选文件的动作。相同报告重放只读回历史记录，不重新授予旧结论。角色标识沿用现有可信操作者接口，不把不同字符串宣称为已验证的外部身份或受控模型独立性。

被冻结审查策略管理的人工条件不能再由普通人工确认或直接检查写入绕过；报告必须匹配当前候选、结果、审查人和依据。新尝试继承该策略，但不复制旧报告；共享准备入口禁止降低原验收条件，Worker 修订后须形成新冻结候选并重新审查。审查通过只满足相应人工条件，不跳过其他必需检查。文件变化本身不承诺自动监视或自动重验，仍通过明确冻结/重新验收开始新轮次。

任务页可冻结成果、下载冻结内容、逐文件填写阻塞缺陷与建议、提交通过/返工/阻塞，并查看历史报告与摘要。产出者和当前负责人不显示独立审查提交按钮；受保护条件隐藏普通确认按钮。网络失败保留冻结编号或报告内容供相同请求重试，错误提示保留版本与完整性原因。所有文件内容以下载方式提供，不把候选脚本载入主进程。

### 跨尝试总截止、累计费用与未知占额

首次准备支持显式 `total_timeout_ms`（1000–86400000 毫秒）和 `total_budget_usd`（正有限美元数）。公开 MCP 入口为 `craft_task_run_prepare`，共享服务准备及知识绑定兼容入口沿用同一实现；不重新广告已经退役的阶段级 MCP 名称。总时间从首次准备计时，包含审批等待、暂停与返工，后续尝试继承固定截止时间；不能在重试请求中增额、延时或重置。未配置总限制的旧记录保留原行为，不补造历史预算。

累计费用复用每次内部派发的现有预算账户，沿根启动的唯一后续链汇总已结算和预留金额，不另造累计计数。原尝试和新尝试都读到整条链的当前值；跨任务、循环、过长、分叉、错误账户归属、损坏余额或已发生模型请求后账本缺失均拒绝继续。十进制加减沿用已有 BigInt 对齐实现。下一次派发的美元上限取其原单次限制与整链剩余额度较小值；报价、预留及实际结算仍由内部 Host 执行。未知调用即使预留金额为零也阻止继续；人工对账按实际入账，超额不增加原总额度。

共享准备和 Host Run 登记在执行前复核总预算，写入审批在授予/消费授权前复核；Codex、Claude、通用 CLI 和内部 Host 的直接驱动路径同样绑定所属启动的总截止取消信号。取消依赖执行器响应，忽略信号时仍等待真实结果，不伪造已停止。已经产出的成果仍可查阅与验收，总限制阻止的是新执行，不能用超时自动跳过质量门或替代副作用对账。

活跃且需要继续执行的 Task Run 耗尽后显示 `attempt_budget_exhausted`，进入补充证据、对账或重新规划；控制台产生人工待处理项。最新尝试仍在运行时不提前宣称已停止，已有后续尝试的历史节点不重复提醒，用户明确取消尝试后解除对应待处理。任务页显示总已用、未知占额、剩余美元和固定截止时间，未设美元总额显示未设置而非零费用。

累计美元限制目前只接受具备固定单价和可信输入报价的内部 Host。默认 HTTP/Codex 模型传输没有可信报价时继续明确拒绝，原生 CLI 不能因可上报部分用量而获得累计美元硬上限；它们已支持总截止控制。费用聚合约束按单条尝试链生效；新根计划与旧链的治理关联、外部真实账单、原生提供方累计计费及带新证据的增额/延时授权仍待完成。不能把手工另建根启动解释为系统已经完成重新规划治理。

### 有证据重新规划、明确批准与单次续做

Task Run、HTTP、MCP 和任务页接通“原执行停止→保存新计划→核对完整指令和证据→批准/拒绝/撤销→按批准创建新尝试”。普通失败、当前验收失败/阻塞或总预算耗尽才具备申请资格；源必须是链末端，所有同链 Host 已停止并确认清理，未知模型费用必须先对账。专用 activation/managed 编排仍回原入口，不能通过通用重新规划丢失合同。

提案固定任务、启动、Host、Task Run、验收、责任、控制合同、任务预算及执行围栏版本，完整新指令存于任务域计划记录。证据必须绑定同一任务、精确版本、未撤销且观察时间不早于源结束；同一证据版本只授权一份被消费的新计划。个人界面支持人工计划变更说明，明确标为人工证据；技术入口的环境修复/新证据类型要求程序确认来源，不把人工声明包装为环境验证。这里仍依赖现有可信调用方与 actor 标识，不新增认证系统。

批准有效期一小时，批准和实际消费都重新检查版本、证据内容、停止状态与费用。批准不执行模型；消费在主库事务内准备新的合同、启动、Task Run、验收与证据使用记录，并切换唯一活动根。写后故障整体回滚，旧批准可重试；两个批准竞争同一源只有一份能消费。提交后才启动只读执行，写入继续等待新审批。重复消费只返回原新尝试，不重复派发；提交后的启动失败通过现有 Task Run Start 恢复。旧启动、原账单和验收结果保留，新尝试继承范围、知识约束、验收与审查策略，不复制旧通过结论。

执行围栏自动覆盖配置总预算的根和开始返工的链；显式申请重新规划也将旧根纳入围栏。纳入后不能另起根绕过限制，已替换根显示 superseded 并拒绝继续执行。尚未进入治理的无限制历史根保留兼容，不宣称全量历史迁移完成。新计划可以明确授权新的总时间和额度，但不增加旧计划额度、不免除旧费用对账。

### 事前风险规则、强制冻结审查与受控返工

Task Control 的 `review_risks` 支持权限变更、数据迁移、跨项目写入、扩展执行边界、资产晋升五类声明；`external_write` 权限自动加入外部写入风险。规则版本固定为 1，准备前记录命中的规则、合同编号/版本、输入摘要及选择原因。风险是结构化合同和可观察权限，不是提示词分类器，也不授予相应操作权限；尚未声明的语义风险不会被假称已经识别。

风险在首次执行前登记，合同仍按原幂等合同不可变。任务级汇总保留已登记风险，另建低风险合同或停用旧合同不能清除风险；新加风险不能给已经执行的旧成果追认“事前”约定。历史外部写入权限可从原合同推导，旧合同的相同请求仍可重读，不覆盖原身份摘要。损坏声明明确拒绝，不默认为低风险。

Task Run 与 WorkControl 的计划/执行准备自动加入必需人工条件 `risk_independent_review`，并要求至少一项必需 `program` 验收条件。调用方不能把独立审查改成可选或模型自评，模型 Reviewer 也不取代程序检查。共享启动入口拒绝风险任务绕过 Task Run 合同；未命中规则的原有低风险路径保留。验收计划创建时就安装冻结策略，不等 Worker 自己选择冻结后才生效；普通人工确认或直接填写检查不能替代当前冻结报告。

风险快照存于启动记录，返工及新计划重新准备时继承风险、程序条件和冻结审查门，但不复制旧结论。写入继续要求新审批。冻结重开当前验收轮次，独立审查和程序检查都针对新轮次；审查失败/阻塞后通过已有有限返工/有证据重新规划继续。WorkControl 的任务语义也保存完整必需条件，避免计划视图少一项门禁。

任务页显示风险名称、规则版本、输入合同版本和必需审查条件；冻结按钮自动选中风险审查条件，保留用户选取成果范围和独立报告操作。风险设置目前通过既有 Task Control HTTP/MCP 或 WorkControl 准备参数提供，不声称所有原生聊天会话或资产晋升入口已自动接入这些任务风险声明。
