# 领域文档

工程技能在探索代码库时应如何消费本仓库的领域文档。

## 探索前，先读这些

- 根目录 **`CONTEXT.md`**
- **`docs/adr/`**：读取与你即将工作的领域相关的 ADR

如果这些文件不存在，**静默继续**。不要标记缺失；不要建议提前创建。`/domain-modeling` 技能（通过 `/grill-with-docs` 和 `/improve-codebase-architecture` 触达）在术语或决策实际被解决时按需创建它们。

## 文件结构

单领域仓库：

```
/
├── CONTEXT.md
├── GLOSSARY.md
└── docs/adr/
    ├── 0001-xxx.md
    └── 0002-xxx.md
```

## 使用词汇表的术语

当输出中出现领域概念（议题标题、重构提案、假设、测试名），使用 `CONTEXT.md` 中定义的术语。不要漂移到词汇表明确避免的同义词。

如果需要的概念尚未在词汇表中，这是一个信号：要么你在发明项目不使用的语言（重新考虑），要么存在真正的缺口（记录给 `/domain-modeling`）。

## 标记 ADR 冲突

如果输出与现有 ADR 矛盾，明确指出而不是静默覆盖。
