# Craft Desktop：操作系统之上的统一任务入口

2026-09-28 补充：用户已明确批准「1 做入口，2、3 一起实现」。即轻入口、并肩协作和成果主界面共用一条 Task 状态链。下文保留原始分析，不再把视觉组合视为待选择；实现和验收进展见 [统一入口实施记录](desktop-unified-entry-implementation-2026-09-28.md)。批准呈现方式不等于批准默认读屏、凭据访问或付费评测。

日期：2026-09-28。状态：产品方向建议，不是已批准实现规格或已交付能力。本轮读取当前 Desktop、Workbench 与产品文档；未运行真实桌面交互，因此以下是源码/产品模型分析，不是截图驱动的视觉或无障碍审计。未修改生产代码、版本、发布物或用户配置。

## 1. 定位与默认假设

建议定位：**Craft 是操作系统之上的个人 AI 任务入口：在用户正在工作的地方接收意图，跨文件、网页与应用完成受控任务，并把可继续编辑的成果交回用户。**

“统一”指意图、任务状态、授权、成果与接续统一，不是把所有应用搬进一个窗口，不是替代 OS，也不是默认拥有全屏、全磁盘和所有账号。它既能轻量出现，也能展开成完整工作空间。专业插件和外部 Host 仍可独立使用。

默认首发面向个人知识工作者，先验证文件/网页/应用协同；团队身份与远程控制不因本定位自动纳入。首发人群仍待用户确认。本轮不以“新一代”或行业热度替代需求验证。

外部一手核验见 [桌面统一入口来源笔记](desktop-unified-entry-primary-sources-2026-09-28.md)。Raycast 官方描述 Quick AI、当前屏幕上下文和工具组合；OpenAI 官方文档区分应用控制、系统权限与应用批准，并建议有专用集成时优先使用；这些支持“轻入口 + 明确上下文 + 受控执行”的设计方向，不证明 Craft 已实现或竞品在任意任务都可靠。[Raycast AI](https://www.raycast.com/core-features/ai)、[OpenAI Computer Use](https://learn.chatgpt.com/docs/computer-use)。Muse 指代及其具体能力本轮仍待确认，不作为强制架构依赖。

## 2. 当前应保留的基础与矛盾

源码已经有对象、待决策项、订阅授权、凭证和非聊天首页，不能概括成“纯聊天壳”。这些基础应保留，但存在以下不一致：

| 已观察事实 | 产品问题 | 建议 |
| --- | --- | --- |
| [Desktop 快捷键](../../desktop/src-tauri/src/lib.rs) 调用 show_main，显示并聚焦主窗口；主窗为完整 Workbench | 快速唤起仍等于切走当前工作，尚不是就地协作入口 | 增加轻量唤起形态；默认不占满屏幕，不强制进入任务中心 |
| [Workbench 导航](../../workbench/app.js) 并列模型、插件、技能、连接器、知识、记忆、工作流 | 普通用户要先理解内部分类，能力管理与日常工作争夺注意力 | 日常入口按“继续、需要你、成果”组织；能力/模型管理移入可发现的高级区域，数据查看、纠错、撤销仍可达 |
| 首页把输入定义为稀有入口，文案认为系统大部分时候应该知道要做什么 | 把“少重复解释”误解为“少表达意图”，容易诱发猜测和未经确认的主动行为 | 输入随时可达，快捷操作只是建议；看不见、拿不准、权限不足就明确说明 |
| “孵化一个新对象”“我的对象”及部分领域枚举直接进入界面 | 领域模型泄露到用户心智 | 面向用户显示报告、报价表、文件整理、待发消息等实际内容；对象仍作为内部通用模型 |
| [桌面控制边界](../technical/modules/desktop-control.md) 明确 Webview 只供人工查看，共享 Control Host 与原生控制链尚未交付 | 打开网页、挂载工具、真的可执行三者仍不同 | 展示按任务实测的可用性，未配置时给具体阻塞，不用统一绿色“已连接”掩盖 |
| [产品概览](../product/overview.zh-CN.md) 同时讲跨 Host 治理插件层、数字工作台和自主 Agent 平台 | 技术供给方式与用户买到的产品混杂 | 对用户只讲一条任务承诺；插件、桌面和无界面只是接入/部署形态 |

## 3. 一个产品，四种相互连续的呈现

| 形态 | 用户何时需要 | 默认呈现 |
| --- | --- | --- |
| 随处唤起的轻入口 | 选中文本、文件、网页，或者突然想到一件事 | 一句意图、明确的上下文标签、少量相关动作；键盘优先，语音作为可选输入 |
| 原位协作面板 | 正在网页或应用里核对、修改、批准 | 当前目标、将修改的内容、预览与纠正；不强迫跳到聊天历史 |
| 专注成果空间 | 写报告、比较方案、修改文件或代码 | 成果占主体，支持类型合适的预览、版本对比和局部修改；对话在旁辅助，不自研全套 Office/IDE |
| 持续事项中心 | 离开后回来，查看多个任务或等待处理 | 继续、需要你、已交付；仅重要变化通知，后台日志按需展开 |

四种形态消费同一 Task/State 与成果引用，不建立四套状态或运行时。全局停机、当前任务暂停、具体动作批准的含义必须稳定且彼此区分。停下不能撤销已经发送的消息；未知执行结果要明确要求核对，不能显示“已全部取消”。

成果优先也不能退化为“审批卡片后台”：阅读、比较、创作、编辑都需要空间，不是所有任务都能简化成一张确认卡。轻量查询可以直接回答，不要求用户手工建项目、选流程或命名对象；确需审计的行为由内核留账，不把所有账本步骤暴露给用户。

## 4. 必须先建立的体验契约

1. **我带进来了什么**：选中材料、来源应用、文件版本与目标范围可见；用户能移除。不可获取时不猜。当前应用内容不是用户指令，也不是执行授权。
2. **你要做什么**：先区分解释、生成草稿、改本地文件和对外提交；跨应用传递资料时说明接收方与范围。
3. **我能怎么纠正你**：自然语言、直接编辑和可发现的快捷操作并存；用户改动触发相关结果重验，不重做未受影响的全部工作。
4. **谁在控制我的电脑**：在用户桌面执行输入时明确显示控制权，允许打断；多任务不能同时争抢同一个窗口或输入焦点。后台并行只在确有隔离环境时成立。
5. **你到底完成了吗**：呈现成果、实际变更和验证结果；模型“完成了”、按钮点击成功和业务终态不是同一个状态。
6. **下次能否接着做**：任务/材料/成果与未解决事项可恢复；续接前检查文件或页面漂移。电脑休眠/应用退出后是否继续取决于真实宿主，不承诺无条件 24/7。
7. **我如何退出这种主动性**：订阅、屏幕/应用访问、记忆、后台预算都可见、可撤销；不默认常录屏或扫描整机。OS 权限批准不代替任务授权。

模型与路由可以提供自动推荐，但自动选择必须受数据去向、费用与权限限制；不能为了“无感体验”隐式切换到云端或更高价供应商。显示不确定的成本/时延为 unavailable，不伪装为零。

## 5. 架构归属：不为展示层另造 Agent

| 位置 | 本方向下的职责 | 明确不负责 |
| --- | --- | --- |
| Desktop | 全局唤起、系统选中内容/分享入口、窗口与控制权提示、系统权限、宿主生命周期 | 领域规划、验收、模型自授权 |
| Workbench/共享视图 | 轻入口、协作面板、成果空间、事项中心的状态投影与用户操作 | 另存一套权威任务状态，生成任意可执行 UI |
| Application 用例/Coordinator | 将用户交互绑定既有 Task、Policy、Activation、Receipt；协调恢复和人工接管 | 直接内联 CDP/平台输入、依赖 MCP 协议实现 |
| Capability + Adapter | 文件、浏览器、应用、代码、内容领域的动作与执行实现 | 因为用户看见某窗口就取得全部权限 |
| 通用 Core | 授权、状态、证据、验收、预算与恢复规则 | 固化成编码流程，或感知具体桌面组件布局 |

这是职责建议，不要求立刻更名目录或增加核心对象。对外产品名建议用 Craft；Workbench 可继续作为实现名称和深度工作视图，而不是所有入口必须经过的大窗口。稳定的控件与操作语义是基本盘，受限的任务特定视图是增强；不把任意模型生成 HTML 当可信审批界面。

## 6. 先验收一条完整体验，再扩能力面

推荐首个纵向场景：用户在已有应用中选中三份材料 → 唤起 Craft → 请求“比较差异并整理成可编辑简报” → 核对上下文与输出位置 → 后台生成 → 在成果空间调整一段 → 关闭再打开仍能接续。发送、分享等外部动作留在明确批准之后，首轮可使用模拟目标。

第二个场景验证授权目录的批量文件整理：先预览、再确认、本地执行、检测冲突和部分失败。第三个验证已有任务的暂停、漂移、重新观察和恢复，而不是增加第十种内容模板。

验收分层：

- **交互原型**：参与者无需先理解 Host/MCP/Skill 即可开始；能说出系统读取了什么、准备改哪里、如何停止。记录首次成功时间、错误入口选择和人工修正成本；不捏造尚未测量的指标。
- **真实执行**：选中材料与 Task 绑定，范围外内容不读/不写；界面变化拒绝过期动作；取消、拒绝、部分完成和 effect_unknown 均可解释。
- **连续使用**：跨窗口不重复讲背景；恢复后不覆盖用户新改动；不因轻入口关闭而误报后台成功。
- **收益**：与用户原有流程相比，切换应用、复制粘贴、等待盯屏和返工确实减少；不能只测模型回答速度。

本轮不把团队 ACL、移动远控、全应用兼容、全天后台自治或全套文档编辑器一起纳入首发。已有可信执行修复继续作为底座，但下一轮产品工作应先确认上述承诺与场景，再选视觉方案、再接真实执行，不继续按后台模块数量推进展示端。
