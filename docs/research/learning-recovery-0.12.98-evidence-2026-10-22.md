# 0.12.98 学习运行时恢复与评测合同修复

日期：2026-10-22。本文区分已发布代码、实际运行、模型执行和效果证明。

## 已确认的问题

1. 新 `.97` 单轮 Worker 首次返回 `skipped_locked`。锁拥有者是存活的旧 `.96` 主 MCP；核对时没有直属学习 Worker，且旧缓存路径已被插件更新清理。只依据锁文件不能宣称学习正在运行。
2. 在确认进程身份、旧缓存缺失及没有模型子进程后，结束旧进程，由正常拥有者检测恢复锁，没有手动删除或强夺锁。
3. 随后 Host 自动重连出 `.97` MCP，存在学习 Worker 与内部 MCP。更新缓存到 `.98` 不会自动替换这些已经启动的进程。交接前先请求旧 Worker 优雅退出并核实其终止，再结束旧主 MCP 及旧维护子进程，没有中断模型任务。
4. 一次手动诊断误用了日常 Context 工具面，缺少后台内部工具。该次错误来自诊断命令，不作为产品业务故障证据。纠正为监督器既有的 `component-context-complete` 工具面后，会话采集成功推进。
5. 真实 `.97` 评测预检读到已审核 Claim，其语义审核包返回 `ready`，但 Worker 最后报告没有已审核 Claim。源码核对确认：Worker 要求 `packet.claim.status`，真实证据包没有这个字段；原测试夹具额外提供了该字段，掩盖合同不一致。

不能据这些证据宣称所有停滞都只有同一个根因。

## 已发布修复

- 监督器重启前检查旧服务器及 Worker 入口是否仍存在。入口因升级清理而消失时，停止无效重试并释放自己的学习锁，报告 `worker_payload_removed`。
- 锁释放共享同一个 Promise。并发停止不会在旧子进程退出前提前释放所有权，也不会重复释放。
- 语义审核包在响应外层提供当前 `claim_status`。证据包本身与 `packet_digest` 的组成不变，不把生命周期元数据混入证据摘要。
- 评测 Worker 使用外层当前状态，缺失或非 reviewed 时不调用模型。更正测试夹具，补状态缺失、撤销及身份不匹配负例。
- 评测任务完成状态绑定 Trace；先完成 Trace，再提交已处理任务状态，避免只记录处理完成而缺少追溯关联。
