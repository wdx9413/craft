# Craft Context 学习遵循最小持久化与作用域晋级

状态：Accepted

Craft Context 是宿主任务的学习入口，不训练或改写 Codex 模型。它只从当前任务及明确授权的注册来源提取线索；原始会话、提示词和工具输入只在任务处理中短暂使用，长期存储限于脱敏后的候选/摘要、来源引用或摘要、版本及治理回执。学习默认留在所属项目。跨项目泛化必须先脱敏，获得独立项目证据，并通过候选生成前绑定的 Evaluation Contract，才能成为用户级资产。每轮默认提供低成本、项目范围的最小充分上下文；高风险、陌生或证据不足任务才按需深度召回。自动演进仅覆盖 Craft 管理的资产；Codex 配置、用户规则及仓库 `AGENTS.md` 不自动修改。自进化 Mod 继续受精确版本信任和权限约束，永远不能取得审批策略能力；Core Policy 由 Runtime 独立执行且不可自改。

## 后果

- 任务入口必须能说明来源、项目范围、所选资产版本、遗漏原因及预算；默认上下文不能隐式检索其他项目。
- Capture 与持久化之间必须有脱敏和类型路由；无法证明安全持久化时保留为任务内线索或丢弃，并提供可解释回执。
- 跨项目晋级不是标签变更。它需要证据独立性、去标识检查及目标作用域合同的完整记录。
- Codex Host 的实际触发、上下文注入、工具调用和任务效果必须有运行回执；单元测试、模拟 Host 或研究基准不能代替真实插件验收。
- 低成本默认路径减少延迟和隐私暴露，但可能漏掉隐含相关经验；深度召回应在明示风险或低证据置信时启用并记录成本。
- 不自动改写宿主配置降低意外影响，但用户级规则改进需要候选、差异展示和明确人工应用步骤。

## 考虑过的替代方案

- 将所有项目的原始对话集中为全局记忆：拒绝。跨项目泄漏和不可验证泛化风险高，且与最小持久化冲突。
- 每轮注入全部知识、经验和记忆：拒绝。上下文成本、陈旧内容误导和范围混用会随规模增长。
- 让学习器直接改写 Codex 规则文件：拒绝。此类文件归宿主/用户管理，应由可审阅的候选变更表达。
