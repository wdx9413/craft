# Agent、Harness、Runtime、Context、State 与 Hook 的边界

Craft 将 `Agent = Model + Harness` 作为产品心智模型，但不把 Harness、Runtime、Context 和 State 合并成一个“智能体内核”。Harness 是可评测的工作策略，负责上下文解析、能力激活、编排、验证与恢复；Runtime 是持久化事实和生命周期内核，负责 Run、Operation、Lease、Checkpoint、Receipt、取消和重试；Context 是给模型/Host 的受限投影；State 是控制态和工作区/外部世界状态的事实源。Hook 只是挂在这些生命周期时点上的扩展 seam，可观察或阻断，但不是 Harness 的第五个组成面，也不能绕过 Permission、Receipt 或 Acceptance。完整 Craft 或 Codex 控制台走 Verified Work Loop，单点 MCP/Skill/插件可以直接提供只读查询或候选操作，但写入、发布和外部 effect 必须回到同一 Control Plane、Policy、Trace、Acceptance 和 Eval。这个决定避免每个组件复制一套账本，也让 Codex 控制台模式与独立 Agent 模式共享证据与恢复语义；实现上允许逐步拆分 `craft-service.ts` 等大门面，但不为了目录整齐把共享内核搬入某个能力包。所有单点能力均用 `mechanism_passed → fixture_passed → conformance_passed → integration_passed → host_verified → business_eligible → routeable` 递进状态评测，MCP 握手或单元覆盖率不能越级成为业务可路由证明。
