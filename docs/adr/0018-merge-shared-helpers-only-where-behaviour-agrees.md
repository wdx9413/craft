# 共享助手只在行为一致处合并，摘要按语义命名

抽取共享助手必须先测量**行为**而不是名字，因为同名不同契约正是这些副本存在的原因。实测结论：`object` 的 35 份完全一致；`text` 的 131 份里 122 份一致，其余 9 份真的不同（`parser-process.ts` 返回未 trim 的值、`trajectory.ts` 额外做 SECRET 检查等），各自保留；`strings` 有 30 份、至少 6 种签名，**不合并**——带 `required` 的 3 份里 `stateful-compute.ts` 多一道守卫，合并会改变行为，因此那道差异留在原处并记录；`noSecret` 有 4 份、**3 种行为**（守卫词表、长度下限、返回类型都不同），**不合并**；`canonical` 有 18 份、14 种写法但**只有 1 种行为**（差异只在参数名与折行），因此**合并**。`canonical` 与 `digest` 对同一种测量给出**相反**结论，这个对比本身是结论：`digest` 有五种行为，它的副本在做不同的事；`canonical` 只是一个书写问题。摘要必须按**语义**命名而不能共用一个 `digest`：`digestJson` 键序敏感、`stableDigest` 键序无关，Craft 用摘要做内容寻址，**选错会静默改变记录的身份**。`craft-service.ts` 的 `fingerprint` 用同一套序列化但返回**裸 hex**（调用方自补 `sha256:`），它有**不同的公开形状**，因此保留原名而不是并入 `stableDigest`。合并这类函数需要一组从**合并之前**的实现取来的金标摘要，因为抽取出来的函数无法用自己证明身份未变——这组金标当场抓到一次真实错误：`undefined` 在数组元素位置被 `Array.join` 渲染成空串、在对象值位置被模板插值渲染成文本 `undefined`，位置不同结果不同，于是"合并后 `[undefined]` 的摘要变了"。最后，跨多文件的文本变换需要独立的验证步骤：用 `\n}\n` 找多行函数结尾在 CRLF 文件上永不匹配，正则因而越过函数继续吞掉后续内容（三个文件的整个类体），而会话工作尚未提交时 git 不构成安全网。
