## 核心模块

| 支柱 | 模块 | 职责 |
| --- | --- | --- |
| 工作与协作 | 目标与协作 | 理解需求，维护目标、约束、偏好、假设与验收条件；澄清、反馈、方向变更和人机交接 |
| 工作与协作 | 共享工作空间 | 文件、结构化对象、素材、计划、版本、细粒度变更、依赖与成果血缘；Canvas、文件树、文档、表格、时间线与状态视图 |
| 工作与协作 | 能力与上下文 | 管理 Skill、工具、MCP、脚本、Workflow、Agent 和资料；按需发现、选择、加载及解释选择依据 |
| 执行与保障 | 规划与调度 | 决定直接执行、复用、探索、委派、并行、等待或询问；管理模型、上下文切片、循环中断、资源预留和预算 |
| 执行与保障 | 执行与连接 | 连接本地程序、模型、Host、标准 API 和必要时的 GUI Adapter；沙箱隔离、凭据句柄、出站控制、挂起唤醒、幂等、提交与补偿 |
| 执行与保障 | 验证与观察 | 收集实际结果，以程序、模型、人工或业务信号检查本次工作；呈现重要变更、失败原因和成本 |
| 学习与改进 | 评测与实验 | 比较能力、检索、记忆、模型、规划、流程和整体交付的质量、稳定性、成本、效率及适用范围 |
| 学习与改进 | 记忆与知识 | 保存事实、偏好、决策和经验，处理来源、范围、更新、冲突、有效期和遗忘 |
| 学习与改进 | 学习与适应 | 从结果、失败及用户修改差异中提出候选改进；检验迁移和历史保持，受控采用或撤回；用户编辑是偏好信号而非自动 Ground Truth |
| 学习与改进 | 编译与复用 | 将稳定方法沉淀为模板、流程、规则、TypeScript 程序或可操作小工具，维护参数、依赖、验证条件和显式 Fallback Trigger |

归属代表主要职责，不是数据隔离：能力选择参考评测，执行读取有效记忆，用户在工作空间查看并修正结果。专业对象和验收方式由领域扩展提供，核心模块不使用研发流程作为所有任务的默认专业模板。

## 贯穿产品的能力

1. **权限、归属与协作治理**：成员与角色、共享和交接、审批范围、操作归属、项目隔离、导出/删除/备份与可选同步。四级自主权 Policy 将动作设为自动、仅通知、单人审批或多人联签；短时授权精确绑定任务、动作、目标与请求摘要，并只能消费一次。平台能力和用户授权共同决定能做什么。
2. **事件、通知与注意力管理**：对话、文件变化、外部事件和定时安排触发工作；区分运行、等待、阻塞和终态，集中呈现待决策项，避免循环通知与重复提问。v0.10.7 已提供跨审批、恢复、后台异常和投机成果的统一 Attention Inbox 投影；它只组织注意力，不替代各源状态机的正式处置。定时执行需要明确的任务与资源授权。
3. **领域扩展与易用性**：连接向导、健康检查、示例、模板、对象编辑器、成果预览、导出与发布。用户可以直接完成第一次工作，之后再保存可复用方法。
4. **成本与资源治理**：任务级软/硬预算，Token、模型/API、CPU/GPU、存储和人工审批时间统一记账；探索或并行前预估并预留额度，超限时缩小范围、暂停、请求追加预算或按策略换模型。模型降级不能绕过质量与风险门禁。

模型与子 Agent 调度是内部手段；用户默认看到任务分工、成果和需要自己决定的事项。团队协作、远程同步和新引导属于规划，不代表当前 CLI 已具备。

## 交互与持续工作

**Generative & Dual-Mode UI（目标）**：保留稳定的导航、项目、运行状态和撤销入口；根据目标装配临时表单、数据看板、分镜板或逻辑图。优先使用受控组件与动作绑定，不让生成界面自行获得执行权限。

人类看到可视化成果，AI 看到有版本的结构化状态、文件引用及所需上下文。两者操作同一权威状态源；任意可编辑字段都要遵循 Schema、权限和提交规则，密钥、审计记录和内部运行变量不作为自由编辑的画布内容。

用户修改后，系统识别受影响成果、标记待复核，并保留未受影响的已接受版本。并发提交检查基线版本，旧结果不能静默覆盖新修改。支持比较方案、试验分支和选择成果；跨会话续接依赖工作状态，不只依赖对话摘要。

完整工作过程：提出目标 → 选择资料与能力 → 计划/试验 → 受控执行 → 检查与修改 → 接受或交付 → 经验候选 → 评测后复用。

## 主动触发与人类干预

Craft 可以由对话、文件变化、Webhook、定时事件或监控信号触发，但“主动”不是无限后台自治：默认只做授权范围内的读取、预取、索引和草稿候选，任何真实写入仍经过 Effect Policy、预算和审批。投机结果必须标记输入版本和有效期，用户没有查看时也能自动过期，不把闲置算力变成隐性账单。

用户看到的是可解释的计划分支、假设、动作、证据、预算与待决策点，可以暂停、取消、调整约束或剪掉尚未执行的分支；Craft 不展示或依赖模型私有思维链。大型 Canvas 通过用户聚焦区域、当前任务和对象依赖形成 Context Viewport，未聚焦内容保留为可重新读取的 Anchor。

## 验证评测与学习

| 能力 | 回答的问题 | 非研发示例 |
| --- | --- | --- |
| 验证 | 本次成果是否满足要求？ | PPT 是否为可编辑的指定格式，报价数据是否有来源 |
| 观察 | 当前发生了什么？ | 哪个镜头在等待生成、哪些文件已修改、费用是多少 |
| 评测 | 哪种方法在一类任务上更合适？ | 两套课件流程的准确性、可编辑性、人工修正时间 |
| 学习 | 下一次应该改变什么？ | 为某类材料选择更可靠的提取方法，停用已过期经验 |

评测独立于单次验证；程序、模型、人工及延迟业务反馈保留来源。主观任务允许多个合格答案，以用户选择或经校准的量表评估；不能把销售转化变化直接当作系统的因果贡献。完整目标包括检索、上下文、记忆、规划及整体交付评测，当前支持范围见 [评测内核](../technical/modules/experience-eval.md)。

## 演进能力与承诺边界

| 方向 | 目标 | 当前与边界 |
| --- | --- | --- |
| 双视角与生成界面 | 界面适应工作，人和 AI 同步修改 | 已有文件快照、版本化工作对象、显式依赖、传递影响分析、待复核状态和旧写入冲突阻断；Canvas、生成组件与自动依赖发现尚待实现 |
| 事务沙箱 | 在适用范围内隔离、预览、检查并提交；失败可恢复或补偿 | 已有策略、本地快照、Docker 一致性驱动、External Effect/Saga 状态机及本地 Broker 补偿 Adapter；不是全世界无损回滚 |
| 轨迹编译/API 组合 | 提炼参数、数据流、分支和验证器，组合稳定操作 | 当前由调用方提供受限 operations，生成静态 TS 候选；未自动从原始轨迹推导完整程序 |
| 上下文虚拟内存（CVMM 类比） | 按需选取资料、工作状态与记忆，保留来源和可重新读取的引用 | 已有能力检索、Context Capsule、范围化记忆和带字符预算的上下文装配；尚无自动摘要/换页策略，不保证突破模型窗口或消除遗忘 |
| 后台经验整理 | 在用户允许的空闲预算内去重、处理冲突、提炼候选并评测 | 已有经验/适应候选协议；尚无自动后台守护整理。保留原始证据，不直接删除审计历史或修改默认策略 |
| 主动感知与投机准备 | 由授权事件提前形成资料索引、恢复工作和候选草稿 | 已有签名 Webhook Subscription、事件收件箱、持久等待、Recovery Queue，以及预算化、可过期的 Speculative Candidate Runtime；公网 Server、环境订阅和内置领域 Worker 尚未实现，不允许默认后台写操作 |
| 成果来源与影响追溯 | 从任意领域成果定位精确输入、转换器、证据和下游消费者 | 已有不可变对象级 Lineage、可选 Locator、上下游有界遍历、环检测和版本陈旧检查；编辑器自动采集、领域 Locator 展示和组织权限尚未实现 |
| 长任务冻结与恢复 | 等待期间释放进程和环境，事件到达后从可验证状态继续 | 已有最小 Dehydration Snapshot、状态指纹、三态恢复检查、短 Hydration Lease、Evidence 完成回执和超时回收；进程内存镜像、跨设备文件搬运和远程对象存储尚未实现 |
| 分级自主权 | 按风险和组织规则决定自动、通知、单人审批或多人联签 | 已有版本化 Policy、精确请求摘要、TTL、唯一审批人、拒绝短路、通知证明和一次性消费；已与配置 Policy 的 External Effect、Runtime/Host Adapter 和一等 Computer Use Operation 原子绑定；真实 GUI Driver 与生产身份认证仍由 Host/网关承担 |
| 动态工具契约 | 让非标准 API、MCP 与 GUI 操作逐步成为安全、可复用能力 | 已有脱敏 Schema Observation、多次一致性推导、人工修订、Sandbox/Evidence Trial 验证、精确版本 Diff、独立批准的 Capability Publication 与版本所有权回滚；自动抓包、真实流量 Canary 和 Host 驱动安装尚待实现 |
| 能力运行灰度 | 用真实任务比较新旧能力并控制退化半径 | 已有精确版本双臂 Canary、稳定分流、最小样本、失败/成本/时延/人工修正指标和自动停止候选流量；统计置信、自动扩量和领域指标 Adapter 尚待实现 |
| GUI 兜底执行 | 无标准 API 时通过受控 Computer Use Adapter 完成必要操作 | 规划能力；GUI 操作低于结构化 API 的可信等级，必须重新观察页面并加强审批，验证码和身份确认交还用户 |
| 组织能力共享 | 在成员授权下复用去标识且经过验证的能力 | 已有 Federation、签名 Hub 增量目录、Materialization，以及将精确 candidate 绑定 held-out Eval、逐 Trial Sandbox Receipt、Evidence、program Grade 与 Signoff 的 Certification；独立批准后才原子晋级 verified，且不自动上传个人轨迹。主动网络传输、深度供应链分析、组织身份、删除治理和管理 UI 尚未实现 |
| 跨宿主治理插件层 | 将多个 Host、Skill/MCP 来源与未来外部 Agent 接到同一证据和权限内核 | 已有 Codex、Claude、DeepSeek Harness 与通用 MCP 接入；本地 Source Mount、签名 Hub、隔离候选与认证形成供给链。远程 Registry Discovery Adapter、A2A Adapter、组织身份和远程执行仍待实现；来源发现不等于信任、激活或执行授权 |

底层采用追加事件、版本化记录和可重建投影表达时间状态；这是一组稳定存储接口，不等于现在就需要自研 Temporal Graph Database。只有当 SQLite/对象存储在并发、查询或规模上出现经测量的瓶颈时再替换后端。

## 对前沿概念的取舍

- 状态并发以字段级 ChangeSet、前置条件和依赖失效为通用基础；CRDT 只用于能定义合并语义的协作对象，不用于审批、付款或任意文件。
- 用户看到计划分支、假设、证据和可取消动作，不展示模型私有思维链，也不把 MCTS 作为产品依赖。
- 外部内容坚持不可信数据与有权限决策隔离；可以使用独立解析进程或模型，但“双模型”不是安全证明，真实边界来自最小权限、Schema、出站控制和回执。
- 用户对成果的修改形成隐式偏好信号，但不是自动 Ground Truth；仍需验证、评测与受控晋级。
- Event Sourcing、关系库、对象存储和图索引是可替换实现。Craft 的壁垒是稳定语义、证据和可重建状态，不是过早自研数据库。
- 主动能力默认限于授权读取、索引、恢复和候选草稿；组织经验必须去标识、可审计、可撤销且经过独立验证，不能自动传播个人原始轨迹。
- 轨迹编译必须声明适用域和 Fallback Contract，收益通过实际质量、成本与耗时评测，不承诺固定倍数。
- 默认 Skill 保持小而可替换：只内置稳定治理和最小澄清边界；模型变强或已验证的领域能力更合适时，应跳过或替换它们。详见[可插拔能力源](../technical/modules/pluggable-capability-sources.md)。

编译可以保留模型判断节点；输入或环境不适用时转回探索。WASM 可作为未来可选执行后端，不能天然提供安全性；Craft 不恢复 Python 运行时依赖。收益按总成本实测，不承诺所有任务都完全跳过推理。
