## 产品定位

Craft 的产品目标是一个人和 AI 共同工作的数字工作台：理解目标、组织能力、执行任务、维护成果，并从经过验证的工作中积累经验。

面向各行业的工作者，不要求用户会编程或理解 Agent 的技术术语。通用内核负责共同的工作机制，领域扩展提供专业对象、视图、工具和验收方式。当前 v0.11.20 交付的是 CLI/插件能力内核与本地 Workbench：已加入共享工作对象、依赖影响分析、范围化记忆、上下文装配、字段级 ChangeSet、持久等待、资源预算、受限 Fallback、能力灰度和可审查的本地能力共享。Source Mount 可保留目录、软链接和镜像等来源；同内容镜像归并为一个逻辑能力，冲突内容明确呈现。Domain Action 已覆盖准备、Schema 校验、一次性授权和证据化报告；受限 Dispatch Bridge、Domain Kit 原子应用、完整数字工作台和远程 Hub 仍在建设规划中。

## 用户得到什么

- **直接开始工作**：提出目标、选择资料，系统在需要时引导连接工具、明确要求和预算。
- **成果可以继续修改**：直接调整文字、表格、镜头或其他对象，保留已接受部分，检查受影响的后续成果。
- **工作可以接续**：项目统一组织任务、资料、决策和成果，支持查找、归档、恢复；跨设备延续是后续目标。
- **执行可以掌控**：看见重要变更、等待原因、已发生费用和待决策项；暂停或取消后知道哪些操作已经发生。
- **结果有判断依据**：交付格式、来源、遗漏、异常和验收结果可查看，模型评价与程序检查明确区分。
- **方法逐渐可复用**：采用现成能力或从真实工作中提炼模板、流程和小工具，减少重复解释与返工。

以上是产品目标，不等于现有 CLI 已支持全部交互。

## 面向各行业

| 用户 | 工作对象 | 适合的界面与验收 |
| --- | --- | --- |
| 视频创作者 | 人物、分镜、素材、镜头、成片 | 分镜板、素材预览、时间线；格式/时长检查与审美选择 |
| 销售人员 | 客户、商机、沟通、报价 | 客户卡片、表格、行动列表；事实核对、发送确认与后续业务反馈 |
| 教育工作者 | 学习目标、知识点、练习、反馈 | 课程视图与练习面板；内容正确性、难度适配和学习反馈 |
| 内容创作者 | 选题、资料、稿件、渠道版本 | 文档、选题板、版本对比；来源、风格与可编辑交付 |
| 研发人员 | 需求、代码、用例、问题、证据 | 编辑器、任务板、差异视图；测试与需求验收 |

研发和视频是首批验证场景，不决定内核只面向技术用户。各行业共用目标、对象版本、依赖、执行、验证、评测和经验机制，不强制共用同一种界面。

## 三大支柱

| 支柱 | 用户价值 | 对应核心模块 |
| --- | --- | --- |
| 工作与协作 | 目标明确、资料可见、成果可编辑、工作可延续 | 目标与协作、共享工作空间、能力与上下文 |
| 执行与保障 | 行动可控、运行可恢复、结果可检查 | 规划与调度、执行与连接、验证与观察；包含沙箱、权限、快照及补偿边界 |
| 学习与改进 | 方法可比较、经验可维护、重复工作更省力 | 评测与实验、记忆与知识、学习与适应、编译与复用 |

完整定义见 [产品架构](architecture.zh-CN.md)。可生成界面、双视角状态、沙箱、轨迹编译、上下文分层和后台经验整理均纳入目标，不因分阶段交付而移除。

## 使用方式与当前边界

长期支持独立工作台/CLI、调度已有 AI 应用、作为其他应用的能力提供方，三者共享内核。Agent、Supervisor、Provider 是执行部署方式，不应成为普通用户开始工作前必须理解的分类。

当前 `craft init` 仍要求选择模式；新的目标驱动引导尚未实现。当前可用入口是 Provider/CLI：能力检索、持久任务与证据、确定性 Workflow、受控编排和评测协议；已有文件快照、本地事务记录、静态脚本候选、精确的 Domain Action Dispatch Bridge 及 Host 交接。桌面 Canvas、自动通用 Host Driver、通用跨设备同步和自主经验编译尚未完成。

已有本地隔离适配雏形与 Docker CLI Adapter/Conformance Suite，但不能宣称完整安全沙箱：远程 Adapter、真实 Secret Broker/出站代理、镜像供应链及 Docker Desktop/Linux Engine 的平台认证仍需补齐。文件快照不等于外部 API 或数据库的无损撤销。详见 [沙箱与执行策略](../technical/modules/execution-policy.md)。

配置、索引、运行记录等 Craft 管理数据默认位于 `~/.craft_data`；业务文件可保留在用户选择的原目录。可选同步应独立启用，不默认上传个人资料，也不要求把全部外部业务数据迁入 Craft。

## 差异点如何验证

差异假设是：用户可以修改工作，系统据此可靠续做，经过验证的方法逐渐变成可维护的能力。单个搜索、沙箱、画布或脚本生成功能不视为独有优势。

用真实任务比较交付质量、人工修正时间、重复解释与重做、恢复成功率、总成本和历史能力回归。成本包括学习与评测开销；不预设“提速 100 倍”“零风险”或“成本近乎为零”。
