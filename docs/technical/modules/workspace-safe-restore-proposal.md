# 工作区安全恢复方案

**状态：草案，未实现。** 首批只讨论 macOS 本机文件工作区；其他系统、远端机器和断电一致性另行验证。

## 1. 结论

建议先在 macOS 提供固定版本的原生恢复助手，使用 `renameatx_np` 的 `RENAME_EXCL` 做单次不覆盖重命名；由 Runtime 管理持久日志、授权和人工核对。助手或文件系统不可用时继续拒绝恢复。恢复仍需处理多个路径、数据库记录和外部并发写入，单次系统调用的原子性不能证明整个恢复原子或崩溃安全。

优先复用 Craft 现有任务、Workspace 身份和存储，不另建一套授权或项目真值。恢复先进入独立的受控实现与故障注入，只有通过本方案的门禁才解除当前拒绝。Linux、Windows、远端和不支持独占重命名的文件系统保持未支持，不能静默退回普通 `rename`。

## 2. 已核对事实与限制

| 证据 | 观察 | 不支持的结论 |
| --- | --- | --- |
| 当前工作树 [workspace.ts](../../../core/workspace.ts) | 恢复在检查后明确拒绝，避免覆盖并发写入；路径检查使用逐段 `lstat` | 不证明其余文件操作能抵御检查后的路径替换 |
| `craft` 的 [package.json](../../../package.json) 与 [桌面 Cargo.toml](../../../../craft-workbench/desktop/src-tauri/Cargo.toml) | Runtime 面向 Node 23 及以上；桌面端是独立 Tauri 工程。仓库搜索未发现可直接复用的独占重命名封装 | Cargo 间接依赖或开发机工具链不代表 CLI、MCP 和已安装包均能使用 |
| macOS 头文件 `sys/stdio.h`，Apple [卷能力说明](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumesupportsexclusiverenaming) | 系统声明 `renameatx_np`、`RENAME_EXCL`，卷可报告是否支持独占重命名 | 不代表全部卷、网络文件系统或操作系统版本都支持 |
| 本机临时目录探针，Darwin 23.3.0 arm64 | `renamex_np(..., RENAME_EXCL)` 对已存在的文件和目录返回 `EEXIST` 并保留源与目标；目标不存在时成功。备份移走后并发创建目标时，发布被拒绝，原备份、新目标和暂存均保留 | 不是正式构建、目标安装包、其他设备或持续并发压力证据 |
| 本机临时子进程探针 | 在备份移动后 `SIGKILL`，原文件仍在备份、目标缺失；在发布后 `SIGKILL`，目标是新文件且备份仍保留 | 没有日志回放、数据库对账或断电持久化证明 |

代码快照以当前工作树为准，基础提交 `aaf9f035d7c00bbe577f091943afd39fba567155`；工作树包含未提交改动，以上代码描述不能等同于固定发布包事实。

## 3. 助手边界与分发

> **Why & What - 受控原生助手**
>
> **What：** 为 macOS 构建小型助手，提供目录句柄锚定的独占移动、必要的文件身份读取和目录同步；Runtime 以版本化窄合同调用。
>
> **Why：** Node 标准 `rename` 不提供不覆盖目标的选项；单纯先检查存在再重命名会有竞态。句柄和独占选项还需配合逐组件不跟随符号链接，单靠路径字符串不够。
>
> **替代：** Python `ctypes` 可快速调用系统函数，但现有安装合同不要求用户安装 Python。Tauri Rust 只覆盖桌面，不覆盖独立 CLI 与 MCP。Node FFI 是较新版本的实验能力，不能扩大现有 Node 版本要求来假装兼容。
>
> **回退：** 助手缺失、摘要错误、架构不匹配、系统调用不存在、卷不支持或无法完成安全打开时，报告不可用并不改变目标文件。

候选形式是独立原生可执行文件或 Node-API 插件，最终由 Runtime 维护者依据进程隔离、可审计性与打包成本选择。两者都要固定协议版本和制品摘要；助手不接收 shell 命令，不自行解析用户意图，不取得额外授权。请求只携带已授权的 Workspace 身份、相对路径、操作标识和所需文件句柄或受控句柄引用；路径、链接和类型在原生边界重新核对。

构建系统需分别产出 macOS arm64 和 x64 制品，与 Craft 固定版本共同发布，锁定源码、编译器、目标系统、架构和哈希。按发行渠道完成签名与必要的公证，离线安装时随包携带；禁止运行时下载或在用户机器临时编译。桌面包、CLI 和 MCP 必须实际读回相同协议及助手摘要。具体签名身份、公证要求和支持的最低 macOS 版本由发布负责人在实现前固定，未验证之前不承诺支持。

## 4. 恢复合同

1. **准备。** 校验用户授权、Workspace 稳定身份、目标卷和助手版本。保存恢复操作 ID，拒绝同一 Workspace 的并发恢复；不同数据空间或外部编辑器不自动共享此锁。
2. **预检。** 验证完整检查点清单，包括空目录、文件类型、相对路径、大小和摘要；拒绝冲突、重叠选区、未知类型及不安全符号链接。估算空间并在不足时退出。现有仅记录文件的历史快照无法证明空目录完整，必须显式标记为不支持完整恢复，不能推断目录不存在。
3. **暂存。** 在同一文件系统创建不可覆盖、权限受限且与操作 ID 绑定的暂存和备份目录。复制快照并再次校验；备份目录不得与用户已有条目碰撞，绝不覆盖。对可同步的文件和目录执行平台支持的持久化操作，失败保留原数据并报告。
4. **日志。** 在任何目标变更前持久化版本化日志：操作 ID、Workspace 身份、检查点摘要、助手版本、每个目标的相对路径、原始身份、预期摘要、暂存/备份引用和步骤。日志及相关目录的持久化顺序须通过故障注入验证；不得将未持久化的意图视为已完成。
5. **逐项操作。** 将原目标安全移至独占备份，记录回执；以 `RENAME_EXCL` 将暂存发布到空目标。目标在间隙被创建时保留新目标、备份与暂存，停止该项及后续项并提示冲突；不删除或覆盖并发文件。每次调用后记录结果，丢失回执时通过文件身份和内容对账，不能盲目重放。
6. **完成与回滚。** 所有项与数据库记录核对后，才报告完成。外部写入可能仍持有已移动文件的句柄，因此不把备份即时删除当作安全前提；保留期限、清理权限和独立验证由数据维护策略明确。失败时只能对确认未发生并发变化的目标采取不覆盖的回滚；无法证明时保留全部候选和日志，转人工处理。

每一步失败均返回操作 ID、当前已确认步骤、保留位置和下一动作，不把部分完成显示为成功。恢复不重建或清理其他项目数据；索引失效与重建另行验证。所有路径检查到实际系统调用之间的符号链接替换必须由助手通过受控句柄与身份校验防护；若无法在目标平台证明，仍保持禁用。

本方案的并发保护面向遵守操作系统权限的其他进程，不假定同一用户下的恶意进程无法修改日志、助手或备份。需要抵抗同权限主动篡改时，必须另行设计隔离身份、可信日志和授权边界；仅靠文件名、目录权限或摘要不能自证。

## 5. 中断与一致性

恢复状态至少区分 `prepared`、`staged`、`applying`、`reconcile_required`、`completed` 和 `manual_conflict`。这些名称是提议中的合同，不代表已有状态机。每个文件的操作还需有独立的准备、备份、发布和核对记录；不能只记录一个全局完成标记。

进程重启后先读取日志、检查助手与 Workspace 身份，再逐项对照目标、暂存和备份。目标已有无法证明归属的内容、备份发生变化、日志不完整或系统调用结果未知时进入 `manual_conflict`，不删除、不覆盖、不自动重试。数据库提交与文件操作不在同一个原子事务中；提交前后均须可识别和核对。若唯一备份位置丢失或其完整性无法证实，恢复保持阻断。

`SIGKILL` 仅模拟进程中断，不模拟突然断电、设备缓存或文件系统损坏。正式宣称断电安全之前，发布负责人须固定硬件、文件系统、同步语义和故障注入方法；未取得证据时明确为未验证。日志记录不能代替独立可恢复备份。

## 6. 验收

| 层次 | 必须验证 |
| --- | --- |
| 原语 | 文件、目录、空目录；目标存在和不存在；源/目标同卷与跨卷；不支持的卷；链接及路径替换；错误码与不覆盖。独立多进程构造目标创建竞争 |
| 恢复 | 快照缺失、摘要不符、磁盘不足、权限失败；多文件每一移动前后注入错误；人工并发创建、替换与打开文件写入；不得丢失当前数据或唯一备份 |
| 中断 | 日志写入、备份、发布、数据库提交和清理每个边界分别终止进程并重开；多次重启与重复请求幂等，未知状态不盲重 |
| 接口 | CLI、MCP、Workbench 对同一身份、授权、冲突和恢复状态一致；不可用时显示原因和人工处理位置 |
| 发布 | 固定版本干净安装，macOS arm64 和 x64 分别读取助手版本、协议与哈希；错误架构、缺失、损坏、旧进程和不支持卷均安全拒绝 |
| 覆盖与证据 | 新增及修改可执行代码增量行和分支覆盖率 100%；报告代码、单测、故障注入和真实 Host 证据，分别列出未测平台与风险 |

## 7. 待决与代价

- Runtime 维护者：选 Node-API 还是独立进程，确定文件句柄传递、进程身份和命令协议；在作出选择前不开始发布承诺。
- 数据与测试负责人：确定外部进程继续写入旧文件句柄时的完成标准、备份保留与人工处理合同；只检查一次摘要不足以证明后续不会再写入。
- 发布负责人：确定 macOS 版本、架构、签名与公证矩阵，并建立固定版本打包及隔离安装流程。
- 测试负责人：定义允许的恢复范围、文件数量与大小、空目录和元数据保真要求、磁盘空间上限，以及冲突与回滚失败的用户体验。

该方案增加平台专属制品、日志空间和人工冲突处理成本；涉及目录树与多文件时没有瞬间全局原子性。不能以短暂禁用覆盖保护、删除暂存或忽略未知结果换取演示成功。
