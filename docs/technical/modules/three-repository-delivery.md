## Hook 延时与并发分片初始化

- 新增 `scripts/smoke/hook-latency.ts`：默认 100 组，每组包含 SessionStart、提交、无操作工具、编辑、Stop、SessionEnd；每次调用使用独立进程，复用预初始化的隔离数据目录。
- 校验开始/结束诊断、Context Receipt 数、关闭且含编辑的回合数和失败事件；不把 CLI 返回 `{}` 当作成功。回执绑定 Hook bundle SHA-256，运行期间替换产物会拒绝出具结果。
- macOS / Node 23.11.0 的最终 600 次调用均通过。六类事件的 P95 为 157～364ms，P99 为 171～423ms，最大 471ms。完整摘要见 [hook-latency-macos.json](../../validation/hook-latency-macos.json)。这只覆盖空仓与隔离数据，不代表大仓、已有资产或生产 P99。
- 并发回归曾复现 `Trace shard records are unavailable`：文件已创建但建表事务未提交，旁路扫描把暂时空的分片当成故障。现在只读扫描对没有任何已提交表的分片返回暂无数据并关闭连接，不缓存该状态；提交后重新读取。已有异常表结构仍拒绝，不增加写锁等待。
- Hook、归档 worker、Trace 分片 42 项回归通过；16 路同时提交信号无失败，P95/最大约 1.334s。它没有达到 500ms 的并发目标，因此完整 Hook 性能项继续保持未完成。
- 归档启动器与 worker 拆开，短命 Hook 不再静态初始化 worker；新增启动器行/分支/函数覆盖 100%。当时主包约 14.2MB，尚包含 TypeScript 编译器；没有证明启动器拆分本身带来可量化提速。后续编译器延迟加载的实测见下文。
- 测试统一遵守 `CRAFT_TEST_HOOK_BUNDLE`，避免同一回归混用源码重建包和旧插件包。源码与本地运行包更新不代表安装的 Codex/Claude 插件已升级。

- 新包 100 组共 600 次串行调用全部通过：六类事件 P95 为 84～230ms，P99 为 91～270ms，最大 350ms。摘要绑定主包和编译器 SHA-256，见 [hook-latency-lazy-typescript-macos.json](../../validation/hook-latency-lazy-typescript-macos.json)。

### 队列竞争、积压与崩溃回归

- 复现两个窗口等待同一个 SQLite 写锁时的竞争：旧实现先读取队首再等待锁，后拿到锁的窗口会将正常竞争误报成发送未知。现在拿到写锁后再检查状态和领取，竞争落败返回 empty；原生发送仍在事务外执行。
- 调度改为只读查询会话标识，每次最多处理 100 个会话，游标遍历后回绕，不读取全体输入正文。真实 1100 条忙碌积压的测试复现并修复了旧前 1000 条扫描导致的饥饿。
- 101 会话分页测试验证推进和回绕；定时器关闭测试验证等待当前派发而保留后续消息；旧已发送数据按批退休，失联映射和临时扫描失败不会停止其他会话。
- 子进程提交领取后被 SIGKILL，重开数据库仍保留 dispatching；后续扫描和重启均不自动重发，其他会话可以发送。已确认发送的正文与历史版本删除，保留无正文回执；task_message 仍为空。
- 调度模块行、分支、函数覆盖率 100%；接口新增原子领取区间的语句和分支均已覆盖。上述清点与队列相关的 89 项回归全部通过，证据摘要见 [project-data-queue-macos.json](../../validation/project-data-queue-macos.json)。以上使用隔离数据库和模拟发送边界，不替代真实双引擎多窗口桌面验收；后续人工核对入口见下文。

## 评测服务入口

- LocalWorkbenchServer 持有 WorkbenchEvaluations，关闭服务时取消并等待本进程评测。
- `POST /api/workbench/evaluations` 接收 operation_id、suite、subject、runtime、workspace（四者为绝对路径）。配置各最多 1 MiB；读取后冻结到独立目录，输入路径和内容摘要共同绑定操作 ID。
- 同一操作和相同输入返回已有记录；输入变化则拒绝；本进程最多 4 个活动评测。普通工作台入口拒绝 in_place，用例只能在隔离工作区执行。
- `GET /api/workbench/evaluations/:id` 获取状态，`GET .../:id/events` 获取有界活动进度，`POST .../:id/cancel` 请求取消，`GET .../:id/report` 读取独立结果目录。均复用 token、同源、请求体边界。
- completed 表示执行与报告已生成，并不等于所有检查 passed。cancelled/failed/unknown 分开记录；服务重启后失去活动进程映射的未决记录返回 unknown，不重放。
- 真实 worker 集成验证了冻结输入、重复提交、输入冲突、状态、进度、报告与取消。工作台面板、版本/产物完整绑定、崩溃后进程核对和 100% 增量覆盖仍未完成。
- 此服务未向 Knowledge 或发布系统签发准入许可；外部报告文件也不能直接获得正式晋级资格。

## 评测执行器崩溃与命令监护

- 后续已真实复现执行器 SIGKILL 后适配命令及其后代仍活着。主执行链现由独立命令监护进程持有实际命令；执行器消失时，以实时 IPC 断开触发清理，不根据存盘历史 PID 猜测归属。适配命令、评分脚本、模型裁判和用例服务均接入，stdin/stdout/stderr 保持系统管道传递。
