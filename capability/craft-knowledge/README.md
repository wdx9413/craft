# @craft/capability-knowledge

Standalone knowledge kernel package. Depends on `craft-common-store-local`, `craft-common-base`, and `craft-common-log`; it does not depend on `craft`. Import the capability descriptor and register it with a `CraftStore` and optional `CraftTelemetry` via `CORE_KERNELS`. The existing Skill and MCP plugin remains the Host-facing surface.

`./claim-governance` exposes Claim save/get/list/review and synchronization. Candidate review requires bounded or confirmed Evidence and an explicit active Source; synchronization marks expired, changed-source/document or bounded contradiction cases for revalidation. Existing source ingestion still handles incremental revisions, deleted files and stale cursors.

Knowledge retrieval evaluation cases may keep the legacy query and expected Claim fields, but those cases are unverified and cannot make a run eligible. A real held-out case must also include `source_session_id`, `source_task_id`, `source_evidence_ids`, `evaluation_channel: "real_session"`, `dataset_partition: "held_out"` and `sanitized: true`. The source Evidence must be confirmed or program evidence bound to that exact session and task. Every expected Claim must have session- and task-bound Evidence from a different session and task. Simulations and development cases remain supplemental. Case creation and evaluation retain provenance status, and evaluation rechecks the referenced Evidence so changed or missing provenance fails closed. Retrieval evaluation never promotes Claims or changes routing by itself. Candidate promotion requires a `candidate_shadow` run bound to the exact candidate revision; every case must have a verified managed Host adjudication (`label_source: "host_adjudicated"`), be real-session held-out, sanitized, and independently evidenced. Caller-supplied `operator_asserted` and `model_candidate` labels remain ineligible. Auto-review rechecks the run and case revisions before promotion.

Candidate-shadow precision and recall measure retrieval against adjudicated labels; they do not establish that using a Claim improved a real task. Session test-log Evidence alone also does not prove a terminal task outcome or Claim benefit. Until a trustworthy independent outcome and effect path is implemented, cases containing `codex_session_program_verification` Evidence fail closed with `insufficient_outcome_evidence`. A passing retrieval run or a Host model judgment must not be reported as proven real-task benefit.

The independent task-effect verifier is not implemented yet. Automatic Knowledge promotion and formal injection therefore currently fail closed, including for earlier retrieval-only promotion records. Candidate-shadow evaluations can still run as retrieval diagnostics; their eligible status does not open the promotion gate.
