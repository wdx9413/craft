# @craft/capability-memory

Standalone memory kernel package. Depends on `craft-common-store-local`, `craft-common-base`, and `craft-common-log`; it does not depend on `craft`. Import the capability descriptor and register it with a `CraftStore` and optional `CraftTelemetry` via `CORE_KERNELS`. The existing Skill and MCP plugin remains the Host-facing surface.

`./memory-governance` exposes policy, proposals, Evidence-backed review, conflicts, approved commit, expiry, topic suggestions, pinned user confirmations and scoped governance tasks. `./memory-capture` accepts explicit statements and Host-classified stable facts into the session tier through explicit source-bootstrap/Evidence ports. The Hook classifier stores stable project conventions and personal preferences only; it does not retain ordinary prompt text. Governed policy commits bounded, conflict-free candidates; repeat observations promote after two independent sessions in one project and three projects globally. At those thresholds, the same explicitly classified topic can automatically supersede a conflicting entry when all aggregated Evidence meets the active policy threshold. The replacement records its conflict resolution and the superseded Ledger entry retains a replacement link. Conflicts below threshold, without qualifying Evidence, or under non-governed policy remain pending. Topic suggestions require confirmation and never overwrite a remembered preference.

Unclassified preference capture checks related, scoped entries before automatic commit. Lexical and programming-language hints require topic or explicit replacement confirmation; hints never assign a durable topic or supersede an old entry. Governed mode also blocks conflicts with Ledger entries created without a candidate. Repeated approved captures can report already-retained active entries without writing them again.

`./contribution` exports `MemoryContribution`, the governed read interface registered by `memoryCapability.contributes`. It owns scoped current/history candidates, current audience/Source checks, validity, topic precedence, confirmation/decay annotations and revision fences. `candidate_mode:true` returns eligible candidates for shared Context ranking; ordinary calls apply local keyword and material budgets. Context retains cross-member ranking, deduplication and pack receipts, and preserves its top-level Memory `items` response. An explicitly supplied Memory provider replaces the legacy default adapter.

Temporal eligibility and topic conflicts are evaluated within each scope before scope precedence. Expired or future task preferences therefore do not hide an effective project preference; valid task preferences still take priority. Historical reads retain all authorized revisions. Bodies excluded by temporal policy are not hydrated.
